Two entry points form a thin bootstrap layer that is independent of business modules:

- `src/index.ts` is the process root. It loads `.env` (searching multiple paths before any other import), initializes TypeORM (`AppDataSource.initialize()`), preloads global permissions, seeds default notification providers, conditionally starts cron jobs per module, lazily connects to Redis (non-blocking fallback to in-memory cache), then calls `createApp()` and listens.
- `src/app.ts` exports `createApp()`, which constructs the Express application: security middleware (helmet, CORS with dynamic origin allowlist + dev subnet/localhost rules, rate limiting with a stricter auth limiter keyed by IP+identifiant), parsing (compression, JSON/urlencoded with 10 MB limit), static file serving (`/uploads`, `/fonds-catalogue` for SVGs with explicit CORP headers), request logging, public routes (`/api/health`, `/api`, `/api/docs`, `/api/docs.json`), the tenant-scoping middleware (`tenantMiddleware` on `/api/`), and then mounts every module controller under its own `/api/<module>` prefix, each guarded by `authMiddleware`, `filterByEtablissement()`, and optionally `requireModuleActive(moduleName)`.
- `src/config/` is a pure configuration facade: `env.config.ts` uses Zod to validate and coerce environment variables (with safe development defaults and crypto-generated secrets), exporting a namespaced `envConfig`; `database.config.ts` builds a TypeORM `DataSourceOptions` object whose entity/migration/subscriber globs switch between `*.ts` (dev) and `*.js` (prod); `swagger.config.ts` holds a hand-written OpenAPI 3.0.3 spec mounted via `swagger-ui-express`; `config/index.ts` re-exports `envConfig` and `databaseConfig`.
- `src/routes/route-registry.ts` defines an alternative declarative registration API (`registerModuleRoutes`) using a `ModuleRoute[]` array plus a `MODULES_CRITIQUES` whitelist so critical modules skip the `requireModuleActive` check — this registry exists alongside the imperative `app.use(...)` mounting in `app.ts` but is not used there yet.

Dependency direction is one-way: `index.ts` → `app.ts` → config + middlewares + controllers; config files depend only on `dotenv`/`zod`/TypeORM and never on controllers or modules.
