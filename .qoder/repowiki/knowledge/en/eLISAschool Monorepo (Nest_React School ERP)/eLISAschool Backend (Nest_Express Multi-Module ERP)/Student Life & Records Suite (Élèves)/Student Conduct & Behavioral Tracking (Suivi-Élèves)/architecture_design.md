Standard three-layer Express module under `src/modules/suivi-eleves/`:
- `entities/`: four TypeORM entities (`IncidentEleve`, `ObservationEleve`, `SanctionEleve`, `FelicitationEleve`) plus a shared `StatutSanction` enum; re-exported via `index.ts`.
- `dto/suivi-eleve.dto.ts`: Zod schemas mirroring the create endpoints, typed against the entity enums so request payloads stay in sync with persistence.
- `services/suivi-eleve.service.ts`: single `SuiviEleveService` class owning one TypeORM `Repository<T>` per entity (resolved through `AppDataSource.getRepository`), exposing CRUD + list-by-student + dashboard methods. A singleton instance `suiviEleveService` is exported for reuse.
- `controllers/suivi-eleve.controller.ts`: an Express `Router` mounting POST `/incidents`, `/observations`, `/sanctions`, `/felicitations` and GET `/eleve/:eleveId/{resource}` plus `/eleve/:eleveId/dashboard`; each route validates the body through the matching Zod schema, injects `utilisateurId` / `etablissementId` from the authenticated request, then delegates to the service.

Dependency direction: controller → service → TypeORM repositories. The service additionally depends on cross-cutting modules — `@modules/auth` (audit trail via `auditService.log`), `@modules/gamification/services` (points attribution for observations/felicities), `@modules/validation-workflow/services` (workflow creation for grave sanctions when `suivi-eleves.sanction.require_validation` is enabled), `@modules/configuration/utils/config.helper` (feature flags), and `@modules/eleves/entities` (to resolve `utilisateurId` from `eleveId`). All external calls are wrapped in try/catch with `logger.warn` so failures are non-blocking.
