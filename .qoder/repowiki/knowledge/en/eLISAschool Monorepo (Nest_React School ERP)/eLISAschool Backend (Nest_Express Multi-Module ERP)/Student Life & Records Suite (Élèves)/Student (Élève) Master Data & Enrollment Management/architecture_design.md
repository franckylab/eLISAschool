Standard Nest-style leaf module organized into four layers under `backend/src/modules/eleves/`:
- `entities/eleve.entity.ts` — TypeORM `@Entity('eleves')` model (`Eleve`) plus `StatutEleve` / `TypeInscription` enums; fields are split into identity, parent/tutor (deprecated in favor of `ResponsableEleve`, kept only for pre-inscription), medical/emergency, school history, enrollment state, and multi-tenancy via `etablissementId`.
- `dto/eleves.dto.ts` — Zod schemas (`createEleveSchema`, `updateEleveSchema`, `preinscriptionSchema`, `convertirPreinscriptionSchema`, `queryInscriptionsSchema`) consumed by `validateDto` in controllers.
- `services/eleves.service.ts` — `ElevesService` class owning a TypeORM `Repository<Eleve>` from `AppDataSource`; encapsulates business rules: parallel uniqueness checks on create, optional validation-workflow gating via `getParamBoolean('eleves.require_validation')`, pre-inscription creation with provisional matricule `PRE-YYYY-NNNNN`, conversion to full enrollment that migrates parents through `parentsService.migrerDepuisChampsDirects`, refusal flow, CSV export/import, and current-class resolution via `AffectationEleve`.
- `controllers/eleves.controller.ts` — Express `Router` exposing REST endpoints guarded by `authMiddleware` + `requirePermission('config:edit'|'personnel:manage')`; public `/preinscription` route resolves `Etablissement` by code before delegating to the service; all routes follow try/catch → `next(error)` convention.

Dependency direction is strictly controller → service → TypeORM repository; cross-module calls go through named imports (`@modules/auth`, `@modules/validation-workflow/services`, `@modules/responsables-eleves/services`, `@modules/classes/entities`, `@modules/annees-scolaires/entities`, `@common/utils`). The module root `index.ts` re-exports entities/dto/services/controllers as a single barrel. Multi-tenancy is enforced by passing `req.etablissementId` down to every query method.
