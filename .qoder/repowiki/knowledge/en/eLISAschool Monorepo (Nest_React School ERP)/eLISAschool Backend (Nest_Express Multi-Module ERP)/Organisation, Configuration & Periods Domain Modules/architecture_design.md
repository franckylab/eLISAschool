Five sibling NestJS-style feature modules, each following a consistent `controllers/dto/entities/services` layering plus a barrel `index.ts` re-exporting sub-folders:

- `organisation/`: TypeORM entities model the school org chart (`Organisation`, `UniteOrganisationnelle`, `Poste`, `NiveauResponsabilite`, `CategoriePoste`, `TemplateOrganisation`) with multi-tenancy via `etablissementId`. Controllers are mounted under a single Express `Router` (`controllers/index.ts` composes `orgController`, `unitesController`, `hierarchieController`, `organigrammeController`, `configController`, `nomenclatureController`). Services encapsulate business logic including PDF organigram generation (`organigramme.pdf.service.ts`) and vacant-post statistics.
- `configuration/`: The most feature-rich module — provides app/module parameter management, a pluggable backup subsystem (interface `IBackupStorage` in `services/storage/storage-provider.interface.ts` with `database-storage.provider.ts` implementation), configuration history, seeding, and a `module-active.middleware.ts` that gates features per establishment. Guard factory `requireConfigPermission` (in `guards/config.guard.ts`) wraps an enum-driven permission matrix (`config-permissions.ts`) and integrates with `@modules/auth` audit logging; prebuilt guards like `canViewConfigApp` / `canEditParams` are exported for controller decoration.
- `types-enum/`: Minimal shared lookup table (`TypeEnum` entity) exposing CRUD endpoints for globally shared enumerations consumed by other modules.
- `periodes/`: v5.0 redesign replaces the old `TypePeriode` enum with a FK to `NiveauPeriode` so each establishment defines its own period levels (trimester, semester, sequence…) and semantic usage; `PeriodeComposition` models the parent-child hierarchy, and `UsageNiveau` attaches semantic tags (evaluation, budget, etc.).
- `requetes/`: Thin admin-request tracker backed by a single `Requete` entity and corresponding service/controller.

Dependency direction is inward: controllers → services → TypeORM entities; cross-module imports use the `@modules/<name>` alias (e.g. `@modules/auth`, `@modules/annees-scolaires`, `@modules/etablissement`). No inter-dependencies exist between these five modules themselves — they are leaf consumers of shared infrastructure.
