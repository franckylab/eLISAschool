Five sibling TypeORM-based modules (`annees-scolaires`, `cycles`, `niveaux`, `filieres`, `specialites`) each follow a uniform barrel layout: `entities/` → `dto/` → `services/` → `controllers/` re-exported from a per-module `index.ts`. The entity graph is strictly layered by academic hierarchy: `AnneeScolaire` owns `Periode`s; `Cycle` owns `Niveau`s; `Filiere` belongs to a `Cycle`; `Specialite` belongs to a `Filiere`. All entities carry an `etablissementId` foreign key plus `@Index(['etablissementId'])` composite indexes for multi-tenancy, and reference the shared `Etablissement` entity via `@ManyToOne` + `@JoinColumn`. Cross-module dependencies flow downward only (e.g. `Niveau` → `Cycle`, `Filiere` → `Cycle`, `Specialite` → `Filiere`); no module imports its parent's service layer. Business logic lives in services that resolve repositories through `AppDataSource.getRepository(...)` and throw `AppError` for domain violations. `annees-scolaires` additionally integrates the shared `validationWorkflowService` and reads runtime toggles via `getParamBoolean('annees_scolaires.require_validation')` to gate creation/clôture behind a two-level approval workflow.
