Three sibling TypeORM/Express sub-modules sharing the same internal layout: `config/` (typed default configuration + `parseConfigValue` helper), `entities/` (TypeORM `@Entity` classes with multi-tenancy via an `etablissementId` UUID column and a `ManyToOne Etablissement` join), `dto/` (Zod schemas re-exported from an `index.ts` barrel), `services/` (business logic per domain — e.g. `scolarite.service`, `depenses.service`, `cantine.service`, `materiel.service`), `controllers/` (one Express `Router` per module exposing REST endpoints under `/finances/*`, `/cantine/*`, `/materiel/*`), and a top-level `index.ts` that re-exports everything for the app bootstrap.

- Finances is the largest: it owns tuition (`FraisScolarite`, `Echeancier`, `Paiement`, `RecuPaiement`), expense lifecycle (`CategorieDepense`, `Depense`, `DemandeDepense`, `BonCommande`, `FactureFournisseur`), accounting/treasury (`EcritureComptable`, `CompteCaisse`, `CompteBancaire`, `MouvementCaisse`) and budget (`Budget`, `LigneBudget`). It additionally ships `cron-jobs.ts` registering five `node-cron` tasks (daily fee reminders, weekly budget alerts, monthly PDF cleanup, Friday financial reports, daily cash-threshold checks) and a `finance-workflow.service` plus `dashboard.service` / `tresorerie.service` for cross-cutting concerns.
- Controllers depend only on their own services and shared `@modules/auth/middlewares` (`authMiddleware`, `requirePermission`); they never import entities or DTOs directly at runtime beyond schema validation.
- Dependency direction is strictly controller → service → TypeORM repository (via `AppDataSource.getRepository(...)` inside services/cron jobs); there is no inter-module coupling between finances, cantine and materiel — each is independently mountable by the root router.
