Each subdirectory is a self-contained Nest/Express module following the same internal layering: `controllers/` (Express routers), `services/` (business logic), `entities/` (TypeORM entities), `dto/` or `dtos/` (validation schemas via class-validator), optional `middlewares/`, `config/`, `utils/`, plus an `index.ts` barrel that re-exports everything. Modules are horizontally decoupled — they depend on shared cross-cutting packages (`@modules/auth`, `@database/data-source`, `@common/utils/logger.util`, `@modules/configuration`) but never on each other except where explicitly needed (e.g. `dashboard` uses `auth` permissions; `validation-workflow` exposes reusable middleware consumed by other modules). Notable specializations:
- `dashboard`: widget registry pattern in `utils/widget-registry.ts` with role/permission-scoped resolution, caching via `dashboard-cache.service`, SSE streaming via `dashboard-sse.service`, and precalculation via `dashboard-precalc.service`.
- `gamification`: background work driven by `node-cron` jobs registered through `initGamificationCronJobs()` / `stopGamificationCronJobs()`, all scheduled in the `Africa/Douala` timezone.
- `transport`: centralized runtime configuration via `config/transport.config.ts` exposing a typed `TransportConfig` interface plus `TRANSPORT_DEFAULT_CONFIG` and a `parseConfigValue` helper.
- `validation-workflow`: provides pluggable Express middlewares (`requireValidationLevel`, `requireActiveWorkflow`) that enforce RBAC per workflow level using `permissionResolverService` and fall back to per-module role maps from the configuration store.
- `utilisateurs`: splits file upload into a dedicated `upload.controller.ts` + `upload.service.ts` backed by multer memory storage with strict MIME filtering.
- `audit`: read-only query module whose only service (`archivage.service`) handles archival/export rather than persistence.
