The backend is an Express application bootstrapped in `src/index.ts` → `src/app.ts`, which registers the NestJS app, mounts all module routers from `src/modules/*/index.ts` under `/api`, and applies cross-cutting middleware (auth, permission, tenant scoping) from `src/common`. Each business area lives as a self-contained folder under `src/modules/<domain>/` following a consistent controller/dto/entity/service layout; modules communicate only through shared services or direct TypeORM entity access — there is no inter-module service registry. All modules share one TypeORM DataSource (`src/database/data-source.ts`) whose migrations live in two parallel trees: `database/migrations/` (SQL/TS feature migrations) and `src/database/migrations/` (TypeORM TS migrations), both driven by scripts in `scripts/`. Multi-tenancy is enforced at the request level by `common/middlewares/tenant.middleware.ts` plus per-entity `etablissementId` columns seeded by `src/database/seeds/system/seed-etablissement-par-defaut.ts`. The `routes/route-registry.ts` centralises route registration so new modules must export their controllers to be picked up at startup.
