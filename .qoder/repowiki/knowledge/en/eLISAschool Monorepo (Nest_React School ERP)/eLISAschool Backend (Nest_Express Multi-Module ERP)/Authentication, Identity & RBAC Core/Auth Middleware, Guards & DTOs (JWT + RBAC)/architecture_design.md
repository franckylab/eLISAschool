Three sub-packages expose a flat barrel (`index.ts`) consumed by controllers:
- `middlewares/` — Express-style functions. `auth.middleware.ts` parses the `Authorization: Bearer <token>` header, delegates verification to `TokenService.verifyAccessToken`, and attaches a `req.utilisateur` object carrying `id/email/role/roles/permissions/etablissementId/etablissements`. `optionalAuthMiddleware` does the same without failing on missing tokens. `permission.middleware.ts` provides `requirePermission` / `requireAnyPermission` / `requireAllPermissions` / `checkPermission` / `requirePermissionWithContext`, which resolve the user's permission set through `permissionResolverService.resolvePermissions(id, etablissementId)` and short-circuit for `SUPER_ADMIN`. `etablissement.middleware.ts` supplies `filterByEtablissement` / `validateResourceOwnership` helpers.
- `guards/` — A parallel Nest-style guard (`permission.guard.ts`) exposing `hasPermission` / `hasAnyPermission` / `hasAllPermissions` / `requirePermissions` with a dual-mode check: first reads `utilisateur.permissions` from the JWT, then falls back to static `DEFAULT_ROLE_PERMISSIONS[role]` from `@shared/enums/roles.enum`; denied access is logged via `auditService.logAccessDenied`. Prebuilt guards like `canViewUsers` are re-exported.
- `dto/` — Pure type layer re-exporting validation schemas from `@shared/validators/auth.validators` under both new names (`LoginInput`) and legacy aliases (`LoginDto`), plus backend-only interfaces `JwtPayload` and `UtilisateurAuth`.
- `cron-jobs.ts` — Top-level initializer calling `initAuthCronJobs()` which schedules an hourly cleanup of stale login attempts via `blocageAuthService.nettoyerAnciennesTentatives()` using `node-cron` in the `Africa/Douala` timezone.
Dependency direction is one-way: middlewares/guards depend on services (`TokenService`, `permissionResolverService`, `auditService`, `blocageAuthService`) and shared enums; they never import controllers or other modules' routes.
