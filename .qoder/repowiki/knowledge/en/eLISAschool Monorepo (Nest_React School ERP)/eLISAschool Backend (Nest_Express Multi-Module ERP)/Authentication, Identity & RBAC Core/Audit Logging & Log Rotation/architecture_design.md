Single-purpose leaf module under `modules/auth` organized by responsibility:
- Entity layer: `audit-log.entity.ts` defines the `@Entity('audit_logs')` TypeORM model plus the exhaustive `AuditAction` / `AuditSeverity` enums shared via re-export from `audit.service.ts`.
- Service layer: `audit.service.ts` (`AuditService`) is the write/read facade — `log()` normalizes UUIDs, extracts client IP / user-agent from an optional Express `Request`, persists via `AppDataSource.getRepository(AuditLog)`, and mirrors to Winston; convenience helpers (`logLogin`, `logPasswordChange`, `logEntityChange`, `logConfigChange`, `logPreferenceChange`, `logCRUD`, `getLogs`, `getAuditHistory`) are the primary integration surface for other modules.
- Domain helpers: `utils/audit-helpers.ts` (sondages, annonces, gamification, sante) and `utils/audit-utilisateurs.ts` wrap domain-specific calls through `auditService.log`, keeping callers decoupled from the raw enum names.
- Admin API: `controllers/audit.controller.ts` exposes `/api/audit/*` routes guarded by `authMiddleware` + `requirePermission('monitoring:view' | 'super_admin:all')`; it delegates lifecycle ops to `auditRotationService`.
- Retention pipeline: `services/audit-rotation.service.ts` (`AuditRotationService`) archives logs older than a threshold into JSON files under `<cwd>/logs/audit-archive`, deletes archives beyond retention, bulk-deletes stale INFO logs, and computes storage stats; `cron-jobs/audit-rotation.cron.ts` schedules weekly rotation (Sunday 02:00 Africa/Douala) and daily stats collection via `node-cron`.
Dependency direction: controllers → rotation service; helpers → audit service → entity; cron → rotation service. No cross-module imports except shared `@common/utils/logger.util`, `@database/data-source`, and `@common/services/redis.service` (unused Redis cache invalidation comment).
