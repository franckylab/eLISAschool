Standard Nest/Express-style vertical slice inside `backend/src/modules/paie/` with four layers:
- `entities/` — TypeORM `@Entity` classes (`BulletinPaie`, `ElementSalaire`, `Cotisation`, `TypePrime`, `TypeRetenue`) plus the `ModeRemuneration` enum; all entities are re-exported from `entities/index.ts`.
- `dto/` — Zod schemas (`createBulletinSchema`, `updateBulletinPaieSchema`, `queryBulletinSchema`) providing request validation and inferred TS types.
- `services/` — Domain logic: `CalculPaieService` is the core, implementing `calculerBulletin()` (upsert + conflict handling via `checkConflict` option) and `simulerPaie()` which branches on `ModeRemuneration` (MENSUEL/HORAIRE/MIXTE/HEBDOMADAIRE), pulls hours from `heureCoursService.getResumeMensuel`, applies active `TypePrime` and `Cotisation` rules per `etablissementId`, and persists `ElementSalaire` detail lines. Other services (`bulletin-paie.service`, `cotisation.service`, `type-prime.service`, `type-retenue.service`) expose CRUD over their entities.
- `controllers/` — thin Express `Router`s mounted under `/paie/*`; each controller delegates to a singleton service instance exported as `xxxService` (e.g. `calculPaieService`).

Dependency direction is strictly one-way: controllers → services → entities + cross-module imports (`@modules/personnel/services`, `@modules/auth/services/audit.service`, `@modules/validation-workflow/services`, `@common/filters/error.filter`, `@modules/configuration/utils/config.helper`). The module root `index.ts` re-exports everything so consumers import from `@modules/paie`. Business rules such as workflow gating (`personnel.paie.require_validation`) and audit logging are invoked conditionally based on config and presence of `userId`.
