Two sibling feature modules following the same internal layering: `controllers/` → `services/` → `entities/` + `dto/`, re-exported from a per-module `index.ts`. Both expose an Express `Router` (`postesController`, `fonctionsController`) mounted by the app root. Controllers are thin: they apply `authMiddleware` + `requirePermission('postes:*' | 'config:edit')`, validate payloads via Zod schemas in `dto/`, then delegate to a singleton service instance exported alongside the class. Services own all persistence through TypeORM repositories obtained from `AppDataSource.getRepository(...)`, enforce multi-tenant isolation by always filtering on `etablissementId` (injected from `req.utilisateur.etablissementId`), and throw `AppError` with typed codes (e.g. `POSTE_CODE_EXISTS`, `FONCTION_EXISTS`, `CIRCULAR_PARENT`).

- `postes/`: no local entity — `Poste` is imported from `@modules/organisation/entities`; the module also re-exports `StatutPoste` / `NiveauResponsabiliteEnum` from that dependency. Business logic includes auto-setting `statut` between `ACTIF`/`VACANT` based on `occupantId`, defaulting `modeRemunerationDefaut` from `TypePersonnel`, and a statistics endpoint aggregating total/actifs/vacants.
- `fonctions/`: owns its own `Fonction` entity (self-referencing `parentId` tree with `niveau` + `chemin` path enumeration). The service maintains tree invariants on create/update (no self-parent, no circular ancestry via `chemin` prefix check), enforces unique `(code, etablissementId)` at the DB index level, and provides a flat list plus a `findArbre` tree builder.
- Cross-cutting helpers: pagination via `paginateWithQueryBuilder` (used by both services); `validateDto` wrapper used in fonctions controller; shared `AppError` and `logger` utilities.
