Express-based module following a thin controller → service → TypeORM entity layering.
- `controllers/` exposes REST endpoints under `/api/scoring-personnel/*` (classement, score/:id, points, regles, recalculer-tous) using Zod schemas from `dto/` for request validation and the shared `authMiddleware` + `requirePermission('config:edit')` guards.
- `services/scoring-personnel.service.ts` is a singleton (`scoringPersonnelService`) owning all business logic: point attribution, per-category score computation (assiduité, comportement, performance, pédagogie), global weighted aggregation, ranking queries with pagination, and CRUD over scoring rules. It holds in-process LRU-style cache (`Map<string, {value; timestamp}>` with 60s TTL) keyed by `etablissementId`.
- `entities/` defines three aggregates via TypeORM decorators: `ScorePersonnel` (aggregated scores/ranks per member/year/period), `RegleScoringPersonnel` (configurable point rules with code uniqueness per establishment), and `HistoriqueScorePersonnel` (immutable audit trail of every score delta). All entities are multi-tenant scoped on `etablissementId` and indexed heavily for ranking queries.
- `cron-jobs.ts` registers four `node-cron` schedules (daily recalc at 23:30, ranking update at midnight, monthly reset on the 1st, weekly history cleanup) gated by feature flags read through `getParamBoolean(...)` from the configuration module; also exports `runScoringRecalculManual` invoked by the admin endpoint.
- Dependency direction: controllers depend only on services and DTOs; services depend on entities and cross-module peers (`@modules/personnel`, `@modules/annees-scolaires`, `@modules/periodes`, `@modules/matieres`, `@modules/classes`, `@modules/auth`, `@modules/configuration`); cron jobs depend on services and data source. The module root re-exports everything via `index.ts`.
