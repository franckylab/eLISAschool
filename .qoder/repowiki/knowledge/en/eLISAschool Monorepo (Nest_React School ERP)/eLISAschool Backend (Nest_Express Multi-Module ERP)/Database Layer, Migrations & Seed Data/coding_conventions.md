- Migrations are fully idempotent: every DDL statement uses `CREATE TABLE IF NOT EXISTS`, `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`, and permission inserts use `ON CONFLICT (code) DO NOTHING` or `NOT EXISTS` guards so re-running is safe.
- Each table follows a uniform column set — UUID primary key via `gen_random_uuid()`, `estSysteme BOOLEAN DEFAULT FALSE`, `createdAt`/`updatedAt` timestamps, plus a dedicated `etablissementId UUID REFERENCES etablissements(id) ON DELETE CASCADE` for multi-tenant scoping.
- Every index is paired with a unique composite on `(code, etablissementId)` (or equivalent natural key + tenant) plus a non-unique index on `etablissementId` alone, ensuring both uniqueness and lookup performance per tenant.
- Permission migrations always insert rows into `permissions` then assign them to roles via `role_permissions` with a `NOT EXISTS` guard, and roll back by deleting all permissions whose `module` matches the feature.
- Seeds are declared as pure async functions returning typed results, registered in `SEEDS_INFO` with explicit `multiTenant`, `idempotent`, `requires`, and optional `defaultPassword` metadata consumed by `getSeedInfo`/`isMultiTenant`/`isIdempotent` helpers.
- Standalone CLI scripts under `scripts/` and `seeds/run-*.ts` bootstrap their own `DataSource` from environment variables, never rely on the app's running instance, and call `process.exit(0|1)` after logging.
