Published as the private npm package `@elisaschool/shared` (`package.json`) with a single barrel entry at `src/index.ts` re-exporting five sub-packages: `enums`, `constants`, `types`, `validators`, `config`. The only runtime dependency is `zod`; everything else is pure TS/JS data — no HTTP, no DB, no framework coupling. Internal layering:
- `enums/` defines the canonical `ModuleName`, `ModuleCategory`, `Role`, `Permission`, `StatutUtilisateur` constants; these are the single source of truth for RBAC and feature flags.
- `config/config.registry.ts` builds a `MODULE_REGISTRY: Record<ModuleName, ModuleConfig>` keyed by `ModuleName`, each entry declaring `defaultRoles`, `permissions`, `dependencies`, `basePath`, `premium`, and `defaultSettings`; helper functions `getModuleConfig`, `getModulesByCategory`, `hasModuleAccess` read from this object. This makes the registry the authoritative model of every app module.
- `types/` exposes cross-cutting interfaces (`IUser`, `IUserProfile`, `IUserWithProfile`, `IUserSession`) composed from the enums above.
- `validators/auth.validators.ts` holds all Zod schemas used by auth endpoints, referencing shared `LIMITS` from `constants/` so validation rules stay in sync with business constraints.
Dependency direction is strictly inward: config → enums, validators → constants/enums, types → enums; nothing in this package imports from any other workspace package.
