Three sibling feature directories with no shared internal layering — each is a self-contained page feature:
- `features/auth/` exposes standalone React page components (`LoginPage`, `ForgotPasswordPage`, `ResetPasswordPage`, `VerifyEmailPage`, `ChangePasswordPage`) plus a decorative `LoginSlideshow`. The login flow is orchestrated through the global Zustand store `useAuthStore` (imported from `@/stores/auth.store`), which owns multi-establishment pre-login data, token lifecycle, and the establishment-selection modal; pages only dispatch actions like `login` / `completeLogin` / `reset`.
- `features/system/components/unauthorized-page.tsx` is a single-purpose route component for permission-denied scenarios; it reads role info via `usePermissions()` from `@/hooks` and navigates back or to `/dashboard`.
- `features/apparence/` is a full CRUD+catalog UI around wallpapers: `ApparencePage.tsx` composes TanStack Query hooks exported from `./hooks.ts` (e.g. `useCatalogueFonds`, `useAjouterFondEtablissement`, `useUpdateConfigRotation`) whose types live in `types.ts`; mutations call `apiClient` against `/api/apparence/*` endpoints and invalidate queries on success so the layout's `FondRotator` picks up changes immediately.
Dependency direction is one-way: features depend on shared `@/components/*`, `@/stores/*`, `@/hooks/*`, and `@/lib/api-client`, but never on each other.
