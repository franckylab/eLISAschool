Three sibling feature folders each expose a single page component plus a `hooks/` data layer and a `types/` schema file:
- `configuration/`: `ConfigurationPage.tsx` is a tabbed shell (`TabId = 'general'|'theme'|'langue'|'modules'|'securite'|'notifications'|'historique'`) that renders either inline forms (general/theme) or delegates to sub-components under `components/` (SecuriteTab, LangueRegionTab, ModulesTab, NotificationsTab, HistoriqueTab). Data access lives in `hooks/use-configuration.ts`, which wraps every REST endpoint behind `@tanstack/react-query` hooks keyed by a central `CONFIG_KEYS` namespace; mutations invalidate the matching query key via `useQueryClient`. The general tab reads/writes establishment info through `useEtablissement` / `useModifierEtablissement` from `@/features/etablissement`; theme changes go through the global `useThemeStore`.
- `parametres/`: `ParametresPage.tsx` presents a searchable, filterable table of `ParametreSysteme` rows with an inline edit modal; its own `hooks/use-parametres.ts` mirrors the same react-query pattern against `/api/configuration/parametres`.
- `maintenance/`: `MaintenancePage` (in `components/maintenance-page.tsx`) shows stats cards + a `DataTable` of interventions driven by `hooks/use-maintenance.ts`.

Dependency direction: pages → feature-local hooks → shared `@/lib/api-client` → backend REST; pages also consume cross-feature stores (`@/stores/auth.store`, `@/stores/theme.store`) and shared UI primitives (`@/components/ui/*`, `@/components/layout/PageHeader`). There is no inter-feature hook sharing — each feature owns its own data layer.
