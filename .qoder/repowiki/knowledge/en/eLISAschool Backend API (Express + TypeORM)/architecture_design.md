Monorepo backend under `backend/` bootstrapped by `src/index.ts`, which loads `.env`, initializes the single TypeORM `AppDataSource` (`src/database/data-source.ts`), preloads RBAC permissions, registers notification providers, starts optional cron jobs, then creates the Express app via `createApp()` in `src/app.ts`. The app composes global middleware in a fixed order: helmet → dynamic CORS → rate limiter (global `/api/` + stricter auth limiter) → compression → JSON/urlencoded parsers → static file servers (`/uploads`, `/fonds-catalogue`) → request logger → public routes (`/api/health`, `/api`, `/api/docs`, preinscription) → tenant-scoping middleware (`tenantMiddleware`) → module route groups. Each business area lives in `src/modules/<domain>/` following a consistent controller/dto/entity/service layout and is mounted as an Express router under `/api/<domain>` with `authMiddleware` + `filterByEtablissement()` + optional `requireModuleActive('<key>')` guards. Cross-cutting concerns live in `src/common/` (filters, interceptors, middlewares, services like Redis, utilities). Configuration is centralized in `src/config/` (`env.config.ts` validated with Zod, `database.config.ts`, `swagger.config.ts`). Migrations are split between SQL files in `backend/database/migrations/` and TS scripts in `backend/scripts/`; seeds live under `src/database/seeds/`. Cron jobs are per-module (`cron-jobs.ts` or `services/cron-jobs.ts`) and registered from `index.ts` when `ENABLE_CRON_JOBS=true` or production.
