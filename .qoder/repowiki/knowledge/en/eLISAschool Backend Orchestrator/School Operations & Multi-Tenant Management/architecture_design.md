- **Modular Monolith Structure**: The module is composed of 16 distinct sub-modules (e.g., `etablissement`, `groupes-etablissements`, `notifications`), each following a strict Controller-Service-Entity-DTO layered architecture.
- **Shared Notification Infrastructure**: The `notifications` sub-module implements a robust Provider Registry pattern (`provider-registry.ts`) with an `INotificationProvider` interface. It supports pluggable delivery channels (Email via Nodemailer, SMS via Twilio, Push via Firebase, In-App) with automatic fallback logic and centralized template management (`notification-templates.service.ts`).
- **Multi-Tenant Consolidation**: The `groupes-etablissements` sub-module enables multi-school management through a `ConsolidationService` that aggregates statistics (students, grades, finances) across multiple establishments, supported by custom access guards (`groupe-access.guard.ts`).
- **Cross-Cutting Workflow & Real-time**: A dedicated `validation-workflow` module provides middleware-based approval chains for various business entities. The `sondages` module integrates WebSocket services for real-time voting updates, while several modules (`notifications`, `gamification`, `sondages`) utilize `node-cron` for scheduled background tasks.
