- The module is split into two sub-packages: `auth/` (authentication flows, JWT lifecycle, audit logging) and `rbac/` (dynamic role/permission CRUD). Entry points are `backend/src/modules/auth/index.ts` and `backend/src/modules/rbac/index.ts`, each exporting controllers, services, entities, DTOs, guards, and middlewares.
- Authentication layer: Express router in `auth.controller.ts` exposes endpoints (`/login`, `/register`, `/refresh`, `/logout`, password reset, email verification, `/switch-etablissement`). Business logic lives in `AuthService` (`auth.service.ts`) which orchestrates multi-mode login (email/pseudonym/matricule/QR/UUID), account lockout, session duration from centralized config, and JWT generation via `TokenService`.
- Token management: `TokenService` (`token.service.ts`) issues short-lived access tokens (JWT signed with `jsonwebtoken`) and long-lived refresh tokens stored in a TypeORM `RefreshToken` entity with IP/user-agent binding, revocation support, and cleanup.
- Middleware/guard boundary: `authMiddleware` validates JWT and attaches `UtilisateurAuth` to `req.utilisateur`. Permission enforcement uses `requirePermissions` guard (`permission.guard.ts`) which checks resolved permissions from the JWT payload, with SUPER_ADMIN bypass and audit logging on denial.
- Permission resolution: `PermissionResolverService` (`permission-resolver.service.ts`) resolves effective permissions by aggregating primary + secondary roles, recursive parent-role inheritance, and per-user GRANTED/DENIED overrides. Results are cached in-memory (5-min TTL) and embedded into JWT payloads at login/refresh time.
- RBAC administration: `rbac/` exposes REST controllers (`roles.controller.ts`, `permissions.controller.ts`, `user-roles.controller.ts`) backed by services for CRUD on roles, permissions, and user-role assignments. All routes require `authMiddleware` plus role-level guards (`requireRoles`).
- Dependency direction: Controllers → Services → TypeORM Repositories / TokenService / PermissionResolverService. Entities (`utilisateur.entity.ts`, `role.entity.ts`, `permission.entity.ts`, etc.) define the data model. No circular dependencies — RBAC services reference auth entities but not vice versa.
