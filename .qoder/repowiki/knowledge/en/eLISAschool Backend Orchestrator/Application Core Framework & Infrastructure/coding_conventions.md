- All API responses follow a standardized envelope format with `success: boolean`, optional `data`, optional `message`, and optional `meta` for pagination — implemented via helper functions (sendSuccess, sendMessage, sendCreated, sendPaginated) in api-response.util.ts.
- Custom errors extend the AppError class with statusCode, code, isOperational flag, and optional details — predefined error instances (UNAUTHORIZED, FORBIDDEN, NOT_FOUND, etc.) are exported as constants in the Errors object for consistent error creation.
- Environment variables are validated at startup using Zod schemas with type-safe inference; invalid configurations cause process.exit(1) in production but fall back to safe defaults in development mode.
- Database connections use a singleton AppDataSource pattern with explicit initialize/destroy lifecycle management — bootstrap and standalone scripts (migrations, seeds) both call AppDataSource.initialize() before operations and AppDataSource.destroy() on completion.
- Multi-tenancy is enforced via tenantMiddleware that extracts etablissementId from JWT claims (supporting SUPER_ADMIN wildcard access, multi-establishment switching via query params, and legacy single-establishment fallback) and attaches it to req.etablissementId for downstream filtering.
