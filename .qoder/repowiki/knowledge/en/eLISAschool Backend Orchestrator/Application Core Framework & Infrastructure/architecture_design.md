- Entry points: `backend/src/index.ts` bootstraps the server by initializing TypeORM's AppDataSource then calling `createApp()` from `backend/src/app.ts`, which configures Express with security (helmet, CORS, rate limiting), compression, parsing, request logging, tenant middleware, module route mounting, and global error handlers.
- Configuration layer (`backend/src/config/`): Zod-based environment validation in `env.config.ts` produces a typed `envConfig` object; `database.config.ts` builds TypeORM DataSourceOptions with dev/prod path resolution for entities/migrations/subscribers; `swagger.config.ts` defines OpenAPI 3.0 specification.
- Database layer (`backend/src/database/`): `data-source.ts` exports a singleton `AppDataSource` initialized at startup with graceful shutdown via SIGTERM/SIGINT handlers; migrations and seeds are standalone scripts (`migrate-rbac.ts`, `run-seeds.ts`) that independently initialize/destroy the connection.
- Common utilities (`backend/src/common/`): Organized into sub-packages — `filters/` (error.filter.ts with AppError class + errorHandler/notFoundHandler), `interceptors/` (request-logger.interceptor.ts, audit.interceptor.ts), `middlewares/` (tenant.middleware.ts for multi-establishment isolation), `utils/` (api-response.util.ts for standardized responses, logger.util.ts, crypto.util.ts, validate-dto.util.ts, qr.util.ts), and `types/` (express.d.ts for type augmentation).
- Dependency direction: index.ts → app.ts → config/env.config + common/utils/logger + database/data-source; app.ts imports all module controllers and mounts them under `/api/*` after tenantMiddleware; common modules depend only on config and express types, maintaining no circular dependencies.
