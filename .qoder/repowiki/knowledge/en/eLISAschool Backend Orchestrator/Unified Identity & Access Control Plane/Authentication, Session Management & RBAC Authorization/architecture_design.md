- **Layered structure**: Controllers (`controllers/`) expose Express routes; Services (`services/`) encapsulate business logic (auth flows, token lifecycle, permission resolution, audit logging); Middlewares/Guards (`middlewares/`, `guards/`) enforce authentication and authorization at request boundaries; Entities (`entities/`) model users, roles, permissions, refresh tokens, and audit logs; DTOs (`dto/`) define validation schemas and response types.
- **Entry point**: `index.ts` re-exports all public surfaces (entities, DTOs, services, controllers, middlewares, guards) for external consumption.
- **Auth flow**: `auth.controller.ts` delegates to `AuthService` which coordinates login/register/password-reset via `TokenService` (JWT signing/verification, refresh-token persistence in DB), `PermissionResolverService` (dynamic RBAC resolution with recursive role inheritance and per-user GRANTED/DENIED overrides), and `AuditService` (security event logging).
- **RBAC architecture**: `permission-resolver.service.ts` resolves effective permissions by traversing role hierarchies (parent roles), merging multi-role assignments, applying user-level permission overrides, and caching results (5-min TTL). `permission.guard.ts` provides middleware factories (`requirePermissions`, `requirePermission`) that check resolved permissions from the JWT payload with fallback to static role-permission mappings.
- **Multi-tenancy support**: Users can be associated with multiple establishments via `UtilisateurEtablissement`; the `/switch-etablissement` endpoint issues a new JWT embedding the active establishment context.
- **Dependency direction**: Controllers → Services → Repositories (TypeORM); Guards/Middlewares depend on TokenService and PermissionResolverService; all layers import from shared enums/validators (`@shared/enums/roles.enum`, `@shared/validators/auth.validators`).
