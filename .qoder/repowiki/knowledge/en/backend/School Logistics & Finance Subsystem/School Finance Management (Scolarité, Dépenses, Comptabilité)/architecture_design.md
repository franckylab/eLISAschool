Layered Express module following the standard `index.ts` barrel → `controllers/` → `services/` → `entities/` + `dto/` split.

- Entry point (`index.ts`) re-exports entities, DTOs, services and controllers so other modules can import from `@modules/finances`.
- `config/finances.config.ts` defines a single `FinancesConfig` interface plus `FINANCES_DEFAULT_CONFIG` covering scolarité, dépenses, comptabilité, trésorerie, budget, dashboard, rapports and workflow; a `parseConfigValue` helper converts env strings to typed values. Services read defaults here rather than hard-coding business rules.
- `controllers/finances.controller.ts` is one Express Router exposing REST routes grouped by domain: `/scolarite/*`, `/echeanciers/*`, `/paiements`, `/remises`, `/impayes`, `/relances/*`, `/depenses/*`, `/dashboard/*`, `/config/*`, `/workflow/*`. Every handler uses a local `validate(schema, body)` wrapper around a Zod schema to throw `AppError(400, 'VALIDATION_ERROR')`, then delegates to a service while pulling `etablissementId` / `userId` from the JWT-patched request.
- `services/` contains one class per sub-domain (`ScolariteService`, `DepensesService`, `ComptabiliteService`, `TresorerieService`, `BudgetService`, `FinanceDashboardService`, `FinanceWorkflowService`) plus `cron-jobs.ts` which registers five `node-cron` schedules (daily unpaid-detection & reminders, weekly budget alerts, monthly PDF cleanup, Friday reports, daily cash-threshold checks) via `initFinanceCronJobs()` / `stopFinanceCronJobs()`.
- `entities/` are TypeORM `@Entity` classes mapped to tables `frais_scolarite`, `echeanciers`, `paiements`, `recus_paiement`, `categories_depense`, `depenses`, `demandes_depense`, `bons_commande`, `factures_fournisseur`, `ecritures_comptables`, `comptes_caisse`, `comptes_bancaires`, `mouvements_caisse`, `budgets`, `lignes_budget`; every entity owns an `etablissementId` FK for tenant isolation and uses `@Index` on hot query columns.
- `dto/` holds only Zod schemas (`createXxxSchema`, `queryXxxSchema`) and their inferred TypeScript types, consumed directly by the controller's `validate` helper — no separate request/response classes.
- Dependency direction is strictly inward: controller → service → TypeORM repository (via injected DataSource); cron jobs call services directly; config is read-only at runtime.
