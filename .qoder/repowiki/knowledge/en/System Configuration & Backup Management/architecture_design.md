- **Layered Architecture**: Follows a standard Controller-Service-Entity pattern. Controllers (`configuration.controller.ts`, `backup.controller.ts`) handle HTTP requests and validation, delegating to specialized services.
- **Core Services**: `ConfigurationService` manages CRUD for app settings, modules, and system parameters with in-memory caching. `ConfigurationHistoryService` handles audit trails and point-in-time restoration. `ConfigBackupService` and `DatabaseBackupService` manage snapshotting and database-level exports.
- **Storage Abstraction**: Uses a provider pattern (`IBackupStorage`) with a `DatabaseStorageProvider` implementation to store backup blobs, allowing for future extensibility to S3 or filesystem storage.
- **Event-Driven Updates**: Implements a singleton `ConfigurationListener` (EventEmitter) to broadcast configuration changes, enabling other modules to react to updates (e.g., cache invalidation) without tight coupling.
- **Multi-Tenancy**: Entities like `ParametreSysteme` and `ConfigurationModule` support an optional `etablissementId`, enabling global defaults with establishment-specific overrides resolved via fallback logic in the service layer.
- **Security**: Access is protected by role-based guards (`config.guard.ts`) and permissions defined in `config-permissions.ts`, ensuring only authorized roles (Admin/Super Admin) can modify critical settings.
