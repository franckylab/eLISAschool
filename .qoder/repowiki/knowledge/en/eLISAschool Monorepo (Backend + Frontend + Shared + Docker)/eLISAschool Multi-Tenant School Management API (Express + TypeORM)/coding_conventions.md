- Each feature module follows a fixed folder layout (`controllers/`, `dto/`, `entities/`, `services/`, optional `guards/`, `middlewares/`, `cron-jobs.ts`) and re-exports everything through an `index.ts` barrel used by `src/modules/index.ts` and `src/app.ts`.
- Route registration in `src/app.ts` uses a uniform middleware chain `authMiddleware → requireModuleActive('<module>') → filterByEtablissement() → controller`, with sub-routes mounted before their parent generic route to avoid path capture conflicts.
- Entities are TypeORM classes decorated with `@Entity`, `@Column`, `@Index`, `@BeforeInsert`/`@BeforeUpdate` hooks for side effects (e.g. password hashing), and use UUID primary keys with `@PrimaryGeneratedColumn('uuid')`.
- All API responses follow the `{ success, data?, message?, meta? }` envelope produced by helpers in `common/utils/api-response.util.ts`, with pagination metadata supplied by `pagination.util.ts`.
- Cross-cutting concerns (error filters, request logger interceptor, audit interceptor, tenant middleware) live in `src/common/` and are imported via `@common/*` path aliases rather than relative imports.
- Configuration is centralized under `src/config/` (`env.config.ts`, `database.config.ts`, `swagger.config.ts`) and read through `@config/*` aliases, with environment-specific behavior toggled by `envConfig.app.isDevelopment` / `isProduction` flags.
