Monolithic Express application bootstrapped from `src/index.ts` which loads `.env`, initializes the single TypeORM `AppDataSource` (`src/database/data-source.ts`), preloads global permissions, registers notification providers, optionally starts Redis, then delegates HTTP setup to `createApp()` in `src/app.ts`. `app.ts` wires security middleware (helmet, CORS, rate-limiting with separate auth limiter), compression, static uploads, Swagger UI, then mounts every module's controllers under `/api/<module>` using per-route middleware chains: `authMiddleware` → `requireModuleActive('<module>')` → `filterByEtablissement()` → controller. Each business domain lives under `src/modules/<domain>/` with a consistent layout of `controllers/`, `dto/`, `entities/`, `services/` plus optional `guards/`, `middlewares/`, `cron-jobs.ts`; cross-cutting concerns live in `src/common/` (filters, interceptors, middlewares, utils, DTOs) and shared config in `src/config/`. The database layer is split between raw SQL migrations under `backend/database/migrations/` (numbered `NNN-<desc>.sql`) and TypeScript migrations under `src/database/migrations/` (timestamp-prefixed `1783507895000-<Name>.ts`), both consumed by the same `databaseConfig` which switches paths based on `isProduction`. Seeds live under `src/database/seeds/` with runner scripts; ad-hoc data-fix scripts sit under `src/database/scripts/` and `backend/scripts/`. Cron jobs are initialized per-module via `initXxxCronJobs()` functions gated by `ENABLE_CRON_JOBS` or production env.
