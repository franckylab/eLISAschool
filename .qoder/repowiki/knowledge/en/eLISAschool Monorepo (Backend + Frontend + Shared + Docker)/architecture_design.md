The root `package.json` declares `backend`, `frontend`, and `shared` as npm workspaces so all three TypeScript packages share a single dependency tree and can be built/linted/tested in one pass via `npm run build|test|lint --workspaces`. The `dev` script launches both `backend` and `frontend` concurrently, while `db:migrate`/`db:seed` delegate to the backend's TypeORM CLI. Cross-cutting infrastructure is provided at this level by `docker-compose.dev.yml` / `docker-compose.yml` (in `docker_infra`) which provision PostgreSQL, Redis, pgAdmin, and optional app containers across local-dev, local-prod, cloud-dev, and cloud-prod profiles; top-level `docker:*` scripts are thin wrappers around compose commands. A `postinstall` override pins `@types/express` vs `@types/express-serve-static-core` to resolve a known type conflict that surfaces when multiple workspace packages depend on Express types. The `shared_package` is the only cross-boundary contract: both backend and frontend import its enums, Zod validators, API/user types, and module registry rather than duplicating them.
