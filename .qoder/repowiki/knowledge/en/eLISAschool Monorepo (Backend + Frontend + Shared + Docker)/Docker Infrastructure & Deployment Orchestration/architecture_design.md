Single-level Docker Compose stack centered on `docker-compose.yml` (default dev compose) plus four environment-specific overlays: `docker-compose.local.dev.yml`, `docker-compose.local.prod.yml`, `docker-compose.cloud.dev.yml`, `docker-compose.cloud.prod.yml`. The stack defines five services — `postgres` (16-alpine), `redis` (7-alpine with AOF + LRU eviction), `backend` (Node/Express built from `Dockerfile.backend.dev` with nodemon hot-reload), `frontend` (Node 20 serving Vite dev server), and `pgadmin4` pre-configured via `pgadmin-servers.json`. All services share a single bridge network `elisaschool_network`; persistent data lives in named volumes (`postgres_data`, `redis_data`, `pgadmin_data`). Database initialization is mounted from `init-scripts/` into `/docker-entrypoint-initdb.d`. Nginx reverse-proxy configuration lives in `nginx.conf` and is used by the cloud prod compose overlay. A Bash entrypoint `deploy.sh` selects the compose file and `.env` pair based on `<mode>` (`local-dev | local-prod | cloud-dev | cloud-prod`), auto-detects host IP for local CORS, generates secrets (`DB_PASSWORD`, `JWT_SECRET`, `REDIS_PASSWORD`, `ENCRYPTION_KEY`, `PGADMIN_PASSWORD`) when placeholders are found, and enforces minimum secret lengths in production. Backup/restore utilities live under `scripts/` (`backup-auto.sh`, `backup-manuel.sh`, `restore.sh`, `update.sh`, `install-cron.sh`, `cron-backup.txt`) writing to `backups/{daily,weekly,monthly,manual}/`. `pgadmin.sh` wraps lifecycle commands for the database admin UI.
