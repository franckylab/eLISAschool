- **Layered structure**: Controllers (`controllers/`) handle HTTP routing with Zod-validated DTOs (`dto/`), delegating to services (`services/`) that orchestrate business logic across configuration entities (`entities/`).
- **Core service triad**: `ConfigurationService` manages CRUD for app config, module toggles, and system parameters with in-memory caching (5-min TTL); `ConfigurationHistoryService` logs all mutations to `HistoriqueConfiguration` for audit and rollback; `ConfigBackupService` creates compressed snapshots with SHA-256 integrity checks via a pluggable storage provider interface.
- **Multi-tenant parameter resolution**: `ParametreSysteme` supports establishment-scoped overrides — `getParametre()` resolves by checking scoped record first, then falling back to global (NULL `etablissementId`), enabling per-school customization without duplicating defaults.
- **Event-driven cache invalidation**: `configurationListener` (EventEmitter) broadcasts config changes, cache invalidations, and restore events so other modules can react without tight coupling.
- **Permission guards**: Fine-grained middleware (`guards/config.guard.ts`) enforces role-based permissions (e.g., `CONFIG_PARAM_EDIT`, `CONFIG_BACKUP_RESTORE`) before controller handlers execute, with SUPER_ADMIN bypass.
- **Utility helpers**: `config.helper.ts` provides typed accessors (`getParamNumber`, `getParamBoolean`) with a fast 1-minute LRU-style cache for high-frequency reads across the codebase.
