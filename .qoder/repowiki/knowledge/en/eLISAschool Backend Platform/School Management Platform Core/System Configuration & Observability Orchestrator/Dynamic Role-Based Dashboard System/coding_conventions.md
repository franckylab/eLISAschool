- All service classes export a singleton instance at module scope using the pattern `export const <serviceName> = new <ServiceClass>()` (seen in `dashboard-cache.service.ts`, `dashboard-data.service.ts`, `dashboard-sse.service.ts`, `widget-resolver.service.ts`, `data-aggregator.service.ts`).
- Every controller route handler extracts `utilisateurId` from `req.utilisateur?.id`, throws a 401 `AppError` if absent, and wraps async logic in a try/catch that delegates to `next(error)` for centralized error handling.
- Cache keys follow a colon-delimited hierarchical naming convention embedding context dimensions such as `widget:data:${widgetId}:${etablissementId}:${periode}` or `dashboard:widgets:${userId}:${etablissementId}`, enabling pattern-based invalidation.
- Input validation uses Zod schemas defined in `dtos/dashboard.dto.ts` with a local `validate()` helper that calls `schema.safeParse()` and throws an `AppError('VALIDATION_ERROR')` on failure, applied consistently across all POST/GET endpoints.
