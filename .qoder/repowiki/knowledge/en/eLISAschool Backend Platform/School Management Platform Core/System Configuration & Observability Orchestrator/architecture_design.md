- **Event-Driven Wiring**: The `configuration` module exposes a singleton `ConfigurationListener` (Node.js `EventEmitter`) that broadcasts state changes. Other modules subscribe to these events to invalidate local caches or trigger updates, ensuring consistency without tight coupling.
- **Shared Configuration Access**: The `monitoring` and `dashboard` modules consume the `configuration` module's public API (`config.helper.ts`) to retrieve runtime parameters (e.g., maintenance mode, app version), establishing `configuration` as the central source of truth for system state.
- **Cross-Module Data Aggregation**: The `dashboard` module acts as a consumer orchestrator, using a dynamic `DataAggregatorService` to lazy-load and execute resolvers from other business modules (e.g., students, grades) via reflective service lookups, aggregating disparate data sources into unified widget responses.
- **Layered Caching Strategy**: Each module implements its own caching layer (`configuration` for params, `dashboard` for widget data) with specific TTLs and invalidation strategies, coordinated by the central configuration listener to prevent stale data across the system.
