The module is organized around Docker Compose as the single source of truth for service topology. `docker-compose.yml` defines the default stack (postgres:16-alpine on port 7002, redis:7-alpine on 7003, backend built from `Dockerfile.backend.dev`, frontend via node:20-alpine on 7001, and pgadmin4 on 7004), all connected through a shared `elisaschool_network` bridge. Environment-specific overrides live in `docker-compose.local.{dev,prod}.yml` and `docker-compose.cloud.{dev,prod}.yml`, selected by `deploy.sh`. Two production-grade multi-stage Dockerfiles (`Dockerfile.backend` and `Dockerfile.frontend`) build optimized images using npm workspaces (`shared/` then `backend/`). The `deploy.sh` orchestrant centralizes lifecycle management: it detects mode (`local-dev | local-prod | cloud-dev | cloud-prod`), auto-generates secrets via OpenSSL when placeholders are found, validates production constraints (JWT ≥ 64 chars, DB password ≥ 16 chars, encryption key ≥ 32 chars), auto-detects host IP for CORS, and wraps `docker compose` commands. Supporting assets include `nginx.conf` for static serving, `pgadmin-servers.json` for preconfigured database connections, `init-scripts/` for DB seeding, and `scripts/` for backup/restore/cron automation.
