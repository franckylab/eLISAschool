- Entry point `src/index.ts` bootstraps via `createApp()` in `src/app.ts`, which wires helmet, cors (with dynamic origin allowlist), compression, rate limiting (global + strict auth limiter), request logging, Swagger UI, then mounts every feature under `/api/<module>`.
- Each business area lives under `src/modules/<domain>/` with a uniform layout: `controllers/`, `dto/`, `entities/`, `services/`, optional `guards|middlewares|cron-jobs|providers`, plus an `index.ts` barrel. Modules are re-exported from `src/modules/index.ts` and imported directly by `app.ts` rather than auto-discovered.
- Cross-cutting concerns live in `src/common/`: filters (`error.filter.ts`, `not-found.filter.ts`), interceptors (`audit.interceptor.ts`, `request-logger.interceptor.ts`), middlewares (`tenant.middleware.ts`, `auth.middleware.ts`, `permission.middleware.ts`, `etablissement.middleware.ts`), services (`redis.service.ts`, `cache-metrics.service.ts`) and utilities (`pagination.util.ts`, `validate-dto.util.ts`, `crypto.util.ts`, `image-processor.util.ts`).
- Data layer is centralized through `src/database/data-source.ts` (single TypeORM `DataSource`), with two migration trees: SQL-only files under `database/migrations/` (009→111) and TS-driven migrations under `src/database/migrations/` (002→1798...), both executed via `typeorm migration:run`. Seeds split into `system/` (RBAC, structure académique, super-admin) and `demo/` (sample data), orchestrated by `run-seeds.ts` / `run-rbac-seed.ts` / `run-demo-seeds.ts`.
- Multi-tenancy is enforced at the middleware level: `tenantMiddleware` attaches `etablissementId` from the JWT; `filterByEtablissement()` injects a `WHERE etablissementId = :id` clause on every repository call; `SUPER_ADMIN` bypass is explicit (`allowSuperAdminOverride`).
- Module activation is gated by `requireModuleActive('<key>')` middleware so features can be toggled per tenant; routes also use `authMiddleware` + `filterByEtablissement()` consistently.
- Configuration is loaded from `.env` via `@config/env.config` and exposed to Swagger through `swagger.config.ts`; static assets (uploads, catalogue fonds) are served from `./uploads` and `../public/fonds-catalogue`.
- The current change period focuses on refactoring the `organisation` module (merging Organisation entity into Etablissement, aligning FKs like Poste→HierarchiePersonnel, removing dead `TypeUniteOrganisationnelle`, creating Cameroonian templates) — reflected in migrations 109–111 and the organisation controller being mounted as a critical always-active route.
