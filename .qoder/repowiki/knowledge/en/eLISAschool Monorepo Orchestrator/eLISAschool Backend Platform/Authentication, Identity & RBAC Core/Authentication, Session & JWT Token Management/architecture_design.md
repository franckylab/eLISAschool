Three-file leaf module following a thin-controller / thick-service split inside `backend/src/modules/auth`:
- `auth.controller.ts` is an Express `Router` exposing `/api/auth/*` endpoints (`login`, `register`, `refresh`, `logout`, `logout-all`, `forgot-password`, `reset-password`, `change-password`, `verify-email`, `blocage-status`, `me`, `switch-etablissement`, `pre-login`, `complete-login`, `etablissements-disponibles`). It performs only request parsing via `validateDto(...)` from the shared `../dto` schemas, delegates all business logic to `AuthService`, and applies `authMiddleware` for protected routes.
- `auth.service.ts` (`AuthService`) owns authentication state: credential lookup across multiple identifiers (email/pseudonyme/matricule/qrCodeId/id), two-level brute-force lockout via `blocageAuthService`, multi-tenant establishment resolution through `UtilisateurEtablissement` + `permissionResolverService`, and password/email-reset flows. Security parameters (max attempts, lockout duration, session length, password policy) are read centrally via `getParam*` helpers from `@modules/configuration/utils/config.helper` and cached in-process for 60s.
- `token.service.ts` (`TokenService`) is the sole JWT/refresh-token provider: `jsonwebtoken` signs access tokens with issuer `eLisaschool` and audience `elisaschool-api` using `envConfig.jwt.secret`; refresh tokens are opaque random strings persisted in the `RefreshToken` TypeORM entity with IP/User-Agent tracking, revocation, and a periodic cleanup method.

Dependency direction is one-way: controller → service → TokenService + external collaborators (`blocageAuthService`, `auditService`, `permissionResolverService`, `utilisateurEtablissementService`, `etablissementSelectionService`, `AppDataSource`). Both services export singleton instances (`authService`, `tokenService`) alongside their class constructors, allowing either direct import or DI injection.
