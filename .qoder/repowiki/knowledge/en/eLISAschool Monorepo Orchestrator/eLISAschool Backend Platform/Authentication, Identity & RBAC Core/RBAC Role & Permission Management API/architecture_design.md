Layered Express module under `src/modules/rbac/` with a thin `index.ts` that mounts three sub-routers (`roles`, `permissions`, `user-roles`) onto a single Express Router. Each sub-domain follows the same controller → service → TypeORM repository pattern:
- `controllers/*.controller.ts` — route definitions using `express.Router`, guarded by `authMiddleware` + `requirePermission('roles:manage')`, input validated via `validateDto(schema)` from `@common/utils`, responses wrapped in `successResponse`.
- `services/*.service.ts` — stateless classes (e.g. `RolesService`) instantiated as singleton exports (`rolesService`, `permissionsService`) and accessed directly by controllers; repositories obtained through `AppDataSource.getRepository(...)`.
- `dto/create-role.dto.ts` — Zod schemas plus inferred TypeScript types shared across controllers and services.

Persistence is defined outside this module in `@modules/auth/entities/role.entity.ts` and `permission.entity.ts`: `Role` ↔ `Permission` many-to-many via a `role_permissions` join table, with an optional self-referencing `parentId` for role inheritance and an `etablissementId` scope column for multi-tenant isolation. Services enforce business rules (system-role immutability, parent existence/self-reference checks, deletion-in-use guard) and call `permissionResolverService.invalidateCacheForRole(roleId)` after any mutation to keep the auth cache coherent. The `getUsersWithRole` path reaches into `UtilisateurEtablissement` and a raw `ProfilUtilisateur` query builder to compute per-tenant user counts, reflecting the project's strict multi-tenant model.
