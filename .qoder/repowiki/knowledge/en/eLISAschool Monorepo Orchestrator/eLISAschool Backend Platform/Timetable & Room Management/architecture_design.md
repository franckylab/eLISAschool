Two sibling Nest-style sub-modules sharing the same folder layout (`controllers/`, `dto/`, `entities/`, `services/`, `index.ts`).

- `emploi-du-temps/` exposes a single Express Router (`emploiDuTempsModuleController`) in its `index.ts` that mounts `/repartitions` and `/` sub-routers. Controllers validate payloads via Zod schemas from `../dto` using `validateDto`/`validateQuery`, then delegate to `EmploiDuTempsService`. The service owns all TypeORM repository access (via `AppDataSource.getRepository(...)`) and implements an in-memory greedy scheduler (`creerPlanVide` / `trouverCreneauDisponible` / `marquerCreneauOccupe`) that consumes `PreferenceEmploiDuTemps` and calls `salleAvailabilityService.trouverSallesDisponibles` from the `salles` module — establishing a one-way dependency `emploi-du-temps → salles`.
- `salles/` is a self-contained CRUD + statistics module whose `SalleAvailabilityService` queries both `emploi_du_temps` and `heure_cours` tables to detect time-slot conflicts; it is exported as a singleton (`salleAvailabilityService`) so other modules can reuse it.
- Entities are plain TypeORM classes (`@Entity`, `@Index`, `@ManyToOne`/`@JoinColumn`) with multi-tenancy via `etablissementId`; enums (`JourSemaine`, `TypeCreneau`, `TypeSalle`, `StatutSalle`) live next to their entities.
- Cross-module boundaries: `emploi-du-temps` imports `Salle` from `@modules/salles/entities` and `salleAvailabilityService` from `@modules/salles/services`; `salles` never imports back into `emploi-du-temps`.
- Shared infrastructure used by both: `@common/filters/error.filter` (`AppError`), `@common/utils/logger.util`, `@common/utils/pagination.util`, and `@modules/auth/middlewares` (`authMiddleware`, `requirePermission`).
