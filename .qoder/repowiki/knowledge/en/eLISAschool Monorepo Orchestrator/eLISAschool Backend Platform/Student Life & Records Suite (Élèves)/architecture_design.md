Each child is a self-contained Nest-style Express module (controllers/dto/entities/services + barrel index.ts) mounted centrally in `backend/src/app.ts` under its own `/api/<module>` prefix. Cross-child wiring is purely HTTP-based: controllers are imported from `@modules/<child>` and registered with the same middleware chain (`authMiddleware`, `filterByEtablissement()`, and where applicable `requireModuleActive('<child>')`). There is no direct TypeScript import between children; inter-module relationships (e.g. `diplomes-eleves` referencing an Eleve id, `responsables-eleves` linking to Eleve, `orientation` and `suivi-eleves` both keyed by eleveId) are enforced at the database layer via foreign keys on the shared `Eleve` entity rather than through service-to-service calls. The only cross-cutting concern applied uniformly across all five children is multi-tenant isolation via `filterByEtablissement()` and optional feature-flag gating via `requireModuleActive()`.
