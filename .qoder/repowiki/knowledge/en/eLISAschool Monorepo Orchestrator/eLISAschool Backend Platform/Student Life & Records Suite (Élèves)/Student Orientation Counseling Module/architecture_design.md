Standard Nest-style sub-package layout under `backend/src/modules/orientation/` exposing a single barrel `index.ts` that re-exports entities, DTOs, services, and controllers.

- `entities/orientation.entity.ts`: TypeORM `@Entity` definitions for three tables (`profils_orientation`, `fiches_metiers`, `rdv_orientation`) plus the `TypeFiliere` enum; JSON columns store flexible arrays of interests/aptitudes/recommendations.
- `dto/orientation.dto.ts`: Zod schemas (`createProfilOrientationSchema`, `updateProfilOrientationSchema`, `createFicheMetierSchema`, `createRdvSchema`, `updateRdvSchema`) paired with `z.infer` TypeScript types consumed by the controller.
- `services/orientation.service.ts`: Singleton `OrientationService` instantiated at module load, owning three TypeORM repositories via `AppDataSource.getRepository(...)`. Business logic includes CRUD over profiles/fiches/RDV, an ILIKE full-text search on fiches, and `suggestFilieres` which scores each `TypeFiliere` by keyword-matching strings in the student's aptitudes.
- `controllers/orientation.controller.ts`: An Express `Router` mounting REST endpoints grouped by resource (`/profils`, `/fiches`, `/rdv`). Every mutating route is guarded by `authMiddleware` + `requirePermission('enseignant:manage')` or `config:edit`; read-only routes only require authentication. Request bodies are validated through `validateDto(schema, req.body)` before being forwarded to the service.
- Dependency direction: controller → service → TypeORM repository; no cross-module entity references except shared `TypeFiliere` enum. Cross-cutting concerns (auth, permissions, error filter, logger, configuration helper) come from sibling packages `@modules/auth/*`, `@common/*`, and `@modules/configuration/*`.
