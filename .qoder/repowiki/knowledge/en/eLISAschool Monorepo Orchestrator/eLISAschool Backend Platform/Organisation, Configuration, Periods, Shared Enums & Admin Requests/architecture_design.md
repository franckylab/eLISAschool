Each sub-directory is an independent NestJS-style feature module exposing a barrel `index.ts` that re-exports `entities`, `dto`, `services`, and `controllers`; controllers are mounted onto a single Express `Router` in a local `controllers/index.ts` rather than registering routes directly.

- `organisation/`: TypeORM entities model the school org chart (`UniteOrganisationnelle`, `Poste`, `NiveauResponsabilite`, `CategoriePoste`, `TemplateOrganisation`) with multi-tenancy via `etablissementId`. The refactored schema removes the standalone `Organisation` entity and attaches units directly to `Etablissement`; `organigramme.pdf.service.ts` generates PDF organigrams and `postes-vacants.service.ts` computes vacant-post statistics.
- `configuration/`: The most feature-rich module — provides app/module parameter management, a pluggable backup subsystem abstracted behind `IBackupStorage` in `services/storage/storage-provider.interface.ts` (with `database-storage.provider.ts` as the built-in implementation), configuration history, seeding, and `middlewares/module-active.middleware.ts` that gates features per establishment. Guard factory `requireConfigPermission` in `guards/config.guard.ts` wraps an enum-driven permission matrix (`config-permissions.ts`) and integrates with `@modules/auth` audit logging; prebuilt guards like `canViewConfigApp` / `canEditParams` are exported for controller decoration.
- `types-enum/`: Minimal shared lookup table (`TypeEnum` entity) exposing CRUD endpoints for globally shared enumerations consumed by other modules.
- `periodes/`: v5.0 redesign replaces the old `TypePeriode` enum with FK-backed `NiveauPeriode` so each establishment defines its own period levels (trimester, semester, sequence…) and semantic usage; `PeriodeComposition` models the parent-child hierarchy, and `UsageNiveau` attaches semantic tags (evaluation, budget, etc.).
- `requetes/`: Thin admin-request tracker backed by a single `Requete` entity and corresponding service/controller.

Dependency direction is inward: controllers → services → TypeORM entities; cross-module imports use the `@modules/<name>` alias (e.g. `@modules/auth`, `@modules/annees-scolaires`, `@modules/etablissement`). No inter-dependencies exist between these five modules themselves — they are leaf consumers of shared infrastructure.
