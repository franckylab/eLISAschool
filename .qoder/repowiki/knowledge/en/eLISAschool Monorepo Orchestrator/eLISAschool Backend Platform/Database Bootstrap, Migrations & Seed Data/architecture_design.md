Two parallel directories coexist: `backend/src/database/` (TypeScript runtime) and `backend/database/migrations/` (raw SQL migrations). The TS side centers on a single TypeORM `DataSource` (`data-source.ts`) exported through `index.ts`, with `initializeDatabase()` / `closeDatabase()` helpers used by tests and scripts. Migrations are split into two families — plain `.sql` files in `backend/database/migrations/` (e.g. finance, personnel, academic structure) and TypeScript `MigrationInterface` classes in `src/database/migrations/` (e.g. organisational templates, RBAC changes), both using raw `queryRunner.query(...)` calls rather than entity-driven migrations. Seeds live under `src/database/seeds/` with a strict separation: `system/` contains idempotent bootstrapping (establishments, academic structure, RBAC, finances, EDT, receipts) orchestrated by `initial.seed.ts`'s `runSystemSeeds()`, while `demo/` provides test fixtures; `seeds/index.ts` publishes a `SEEDS_INFO` registry plus `RECOMMENDED_ORDER` and helper predicates (`isMultiTenant`, `isIdempotent`). A standalone CLI entry `seeds/run-seeds.ts` builds its own `DataSource` (with globbed entity paths) and injects it into the shared `AppDataSource` before invoking `runSystemSeeds()`. Auxiliary `scripts/` provide ad-hoc diagnostics (`check-seeds-status.ts`, `analyse-permissions.ts`, `fix-super-admin-permissions.ts`, `update-multi-tenant-structure.ts`). Dependency direction is one-way: seeds and scripts depend on entities from `@modules/*/entities`; migrations do not import application code.
