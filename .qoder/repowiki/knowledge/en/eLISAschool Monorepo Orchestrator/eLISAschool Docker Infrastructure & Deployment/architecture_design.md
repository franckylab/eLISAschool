Single `docker/` leaf that ships the entire runtime stack as a docker-compose application. The root `docker-compose.yml` defines five services on a shared bridge network `elisaschool_network`: `postgres:16-alpine` (port 7002), `redis:7-alpine` (port 7003, AOF + password), `backend` (Node 20 + nodemon hot-reload, built from `Dockerfile.backend.dev` against the repo root), `frontend` (Node 20 Alpine running Vite dev server), and `pgadmin4` pre-wired via `pgadmin-servers.json`. Four compose overlays (`docker-compose.local.{dev,prod}.yml`, `docker-compose.cloud.{dev,prod}.yml`) switch between local IP-based access and cloud domain+SSL modes. A single Bash entrypoint `deploy.sh` selects the overlay by `<mode>` (`local-dev | local-prod | cloud-dev | cloud-prod`), auto-generates secrets in `.env.local` / `.env.cloud` via `openssl rand`, validates production secret lengths, and wraps `docker compose up|down|rebuild|status|logs`. Persistent state lives in named volumes `postgres_data`, `redis_data`, `pgadmin_data`; database init SQL is mounted from `init-scripts/`. Operational scripts under `scripts/` implement daily/weekly/monthly `pg_dump | gzip` rotation into `backups/{daily,weekly,monthly}/` plus manual backup/restore and an installable cron job (`install-cron.sh` + `cron-backup.txt`).
