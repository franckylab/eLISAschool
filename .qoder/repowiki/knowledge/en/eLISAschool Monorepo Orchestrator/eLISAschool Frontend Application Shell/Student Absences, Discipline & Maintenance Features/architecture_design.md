Three sibling feature packages (`absences`, `discipline`, `maintenance`) follow an identical internal layout: `index.ts` barrel re-exports the page component from `components/`, all hooks from `hooks/`, and all types from `types/`. Each feature is self-contained — it owns its own domain types (e.g. `Absence`, `Sanction`, `Intervention`), a set of `@tanstack/react-query` hooks in a single file (`use-*.ts`) that encapsulate REST calls via `apiClient`, and one presentational page component per feature. The hooks are the only boundary to the backend; they call `/api/absences*`, `/api/discipline/sanctions*`, and `/api/maintenance/*` endpoints respectively, read authentication state from the global `@/stores/auth.store`, surface user feedback through `sonner.toast`, and invalidate related query keys on mutations using a module-scoped `*_KEYS` constant (e.g. `ABSENCES_KEYS.listes()`). Dependency direction is strictly inward: components → hooks → apiClient/stores; there is no cross-feature import between the three packages.
