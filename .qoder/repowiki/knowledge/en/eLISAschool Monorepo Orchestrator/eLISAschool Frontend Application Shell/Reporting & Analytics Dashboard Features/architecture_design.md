Each of the three sibling features (`analytics`, `statistiques`, `rapports`) follows an identical internal layout: a thin `index.ts` barrel re-exporting only the page component from `components/`, a `hooks/<feature>.ts` file wrapping every REST endpoint with `@tanstack/react-query` hooks (queries gated by `useAuthStore().isAuthenticated`, mutations that call `queryClient.invalidateQueries` on success), a `types/<feature>.types.ts` file declaring the request/response DTOs, and a single presentational page component in `components/`. The pages consume reusable UI primitives from `@/components/ui/*` (`CardGrid`, `StatCard`, `DataTable`) and are purely presentational — all data fetching, caching keys (`ANALYTICS_KEYS`, `STATISTIQUES_KEYS`, `RAPPORTS_KEYS`), and mutation side effects live in the hooks. Dependency direction is one-way: components → hooks → `apiClient` (`@/lib/api`) → backend `/api/analytics/*`, `/api/statistiques/*`, `/api/rapports/*`; there is no cross-feature coupling between the three sub-packages.
