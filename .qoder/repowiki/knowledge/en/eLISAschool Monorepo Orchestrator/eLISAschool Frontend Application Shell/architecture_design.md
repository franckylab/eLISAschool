The frontend is an application shell (`src/app/App.tsx` → `createRouter`) that bootstraps providers (theme, auth, i18n) and mounts a file-based route tree generated by `@tanstack/router-plugin` under `src/routes/`. Each business domain lives as a sibling folder in `src/features/<domain>/` following the same contract: a barrel `index.ts` re-exports a page component plus typed hooks/types, so routes can import them without knowing internals. Cross-cutting concerns are centralized in `src/components/ui/*` (Radix + Tailwind primitives), `src/hooks/*` (auth, permissions, pagination, breakpoints), `src/stores/*` (Zustand slices for theme/auth/language/sidebar), and `src/lib/*` (TanStack Query client, API wrapper, i18n). Feature modules must not reach into each other's folders; cross-feature communication goes through the shared store layer or REST calls via `lib/api-client.ts`. The current refactors (TypePersonnel/Fonction orthogonality, organisation v4.0 consolidation from 12→8 entities) propagate changes through these shared contracts rather than ad-hoc imports.
