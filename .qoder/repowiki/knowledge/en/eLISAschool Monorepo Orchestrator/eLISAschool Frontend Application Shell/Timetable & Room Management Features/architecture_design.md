Two sibling feature packages under `src/features/`, each following a consistent React + TanStack Query layout:
- `emploi-du-temps/`: entry barrel (`index.ts`) re-exports pages (`EDTStandalonePage`, `EmploiDuTempsListe`, `EDTPreferencesPage`, `EDTTemplatesPage`), UI components (`EDTCalendar`, `EDTGenerationModal`), and the `use-emploi-du-temps.ts` hook module. The standalone page composes a tabbed shell (`calendrier | liste | preferences | templates`) via `TabsBar` and `motion.div`, driving all data through `useCreneaux` / `usePreferencesEDT` / `useTemplatesEDT` which wrap `@tanstack/react-query` calls against `/api/emploi-du-temps*`. A local `EDT_KEYS` object centralises query keys so mutations invalidate the right slices.
- `salles/`: mirrors the same shape — `pages/` (list/detail/statistics), `components/` (forms, selects, modals), `hooks/use-salles.ts`, and a dedicated `types/salle.types.ts` defining `Salle`, DTOs, enums (`TypeSalle`, `StatutSalle`), and cross-resource types (`CreneauEmploiDuTemps`, `ClasseLiee`). The hooks read auth state via `useAuthStore().isAuthenticated` to gate queries.

Cross-feature boundary: `salles` reads timetable slots by calling `/api/emploi-du-temps?salleId=...` directly from `useSalleEmploiDuTemps`, making it a one-way consumer of the emploi-du-temps API rather than importing its hooks. Both features depend only on shared primitives (`@/lib/api-client`, `@/lib/api`, `sonner` toasts, `react-i18next`, `lucide-react`, `framer-motion`) and never import each other's internals.
