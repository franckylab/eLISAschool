Each sub-feature (laboratoire, inventaire, sante) follows an identical self-contained layout: a `components/<feature>-page.tsx` React page, a `hooks/use-<feature>.ts` file wrapping @tanstack/react-query queries/mutations against `/api/<feature>/...`, a `types/<feature>.types.ts` module declaring domain interfaces plus DTOs/filters/stats, and a thin `index.ts` barrel re-exporting the page (and sometimes types/hooks). The three features are orthogonal — they share no internal imports across each other — and depend only on shared UI primitives (`@/components/ui/*`, `@/components/layout/PageHeader`, `@/stores/auth.store`) and the HTTP client (`@/lib/api` or `@/lib/api-client`). Query keys are scoped per feature via local constants (`LABORATOIRE_KEYS`, `INVENTAIRE_KEYS`, `SANTE_KEYS`) to enable targeted cache invalidation after mutations. The sante feature additionally uses a nested key factory pattern (`visites.all → visites.liste(filtres)` / `visites.detail(id)`) for finer-grained cache control.
