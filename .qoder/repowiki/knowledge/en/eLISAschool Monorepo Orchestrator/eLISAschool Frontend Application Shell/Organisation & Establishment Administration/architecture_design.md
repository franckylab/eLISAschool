Three sibling feature packages under `src/features/` each follow a consistent React-Feature-Folder layout: `components/`, `hooks/`, `types/`, plus an `index.ts` barrel that re-exports public APIs.

- `organisation/` is the largest package. It owns the v4.0 consolidated model (EchelonStructurel, UniteOrganisationnelle, HierarchiePersonnel, Poste, ModeRemuneration, NiveauResponsabilite, TemplateStructure/Organisation) declared in `types/organisation.types.ts` with Zod validation in `organisation.zod.ts`. Business logic lives in `hooks/` (`use-unites`, `use-hierarchies`, `use-postes`, `use-templates`, …) which wrap API calls and expose `useMutation`/`useQuery`-style helpers; `components/` composes these into pages (`UnitesPage`, `UniteDetailPage`, `NomenclaturesPage`, `TypesPersonnelPage`, `ModesRemunerationPage`, `GenerationWizard`) and shared UI (`base-form-modal.tsx`, `hierarchie-form-modal.tsx`).
- The organigramme sub-package `components/organigramme/` is a self-contained visualisation layer built on `reactflow`: `OrganigrammeFlowView.tsx` is the entry point, wiring custom `UniteNode` / `HierarchieEdge` components, a DnD state machine (`use-dnd-organigramme.ts`), a layout converter (`use-organigramme-flow.ts` → `utils/layout.ts`), and a toolbar/search/synthese panel. Data flows one-way from the tree API shape into React Flow nodes/edges via `computeLayout`.
- `etablissement/` and `etablissements/` are two parallel establishment features (likely legacy vs. new listing); both mirror the same structure — `components/etablissements-page.tsx` + `hooks/use-etablissements.ts` + `types/etablissement.types.ts` — and are independently exported from their own `index.ts`.

Dependency direction inside the module: `components/` depend on `hooks/` and `types/`; the organigramme sub-tree depends only on its sibling hooks/types and never on other feature packages. Cross-feature imports are minimal (e.g. `OrganigrammeFlowView` uses `useModifierPoste` from `../../hooks/use-postes`).
