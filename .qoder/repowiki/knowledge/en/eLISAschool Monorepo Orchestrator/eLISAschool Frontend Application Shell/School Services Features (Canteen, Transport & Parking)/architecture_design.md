Three sibling feature packages (`cantine`, `transport`, `parking`) follow an identical internal layout: a `types/` folder with server DTOs and filter interfaces, a `hooks/` folder built on `@tanstack/react-query` that owns all API calls via the shared `apiClient`, and a single `components/<feature>-page.tsx` page component wired to `react-i18next` and the global permission system. Each package exposes a barrel `index.ts` re-exporting types, hooks, and the page component so consumers import from `features/<feature>` only. Query keys are centralized in a `FEATURE_KEYS` object using nested arrays (e.g. `['cantine', 'inscriptions']`) so mutations can invalidate related queries by prefix. All pages consume a shared `DataTable` + `PageHeader` + `ElisaButton` UI kit; `cantine` and `transport` pages additionally gate actions through `usePermissions()` with namespaced permissions like `cantine:create`, `transport:delete`. The `parking` feature is slightly older — it uses the legacy `@/lib/api` client instead of `@/lib/api-client`, returns `{ success, data }` envelopes rather than paginated responses, and renders its own stat cards instead of the shared `CardGrid`/`StatCard` components.
