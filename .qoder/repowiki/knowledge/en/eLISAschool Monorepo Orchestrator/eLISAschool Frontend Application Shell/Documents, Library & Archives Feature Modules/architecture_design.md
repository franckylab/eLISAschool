Each sub-feature (`documents`, `bibliotheque`, `archives`) follows an identical three-layer layout: a `types/*.types.ts` file declaring domain DTOs/interfaces, a `hooks/use-*.ts` file wrapping every REST endpoint in a `useQuery` / `useMutation` hook keyed by a module-scoped constant object (e.g. `DOCUMENTS_KEYS`, `BIBLIOTHEQUE_KEYS`, `ARCHIVES_KEYS`), and a single `components/*-page.tsx` page component re-exported through an `index.ts` barrel that also re-exports types and hooks. All HTTP calls go through a shared `apiClient` (`@/lib/api-client` or `@/lib/api`) returning `{ success, data }` envelopes; mutations call `queryClient.invalidateQueries` against their own key prefixes plus a `stats()` key so the dashboard stays consistent after writes. File uploads are handled by constructing a `FormData` body with fields like `fichier`, `titre`, `tags` (JSON-stringified) and triggering a browser download via `URL.createObjectURL` on blob responses. Read-only queries are gated by `isAuthenticated` from `@/stores/auth.store` and use `staleTime` of 5–10 minutes; detail views pass `placeholderData` to avoid flicker. The three features share no internal code — they are parallel implementations of the same pattern, each owning its own API namespace (`/api/documents`, `/api/bibliotheque`, `/api/archives`).
