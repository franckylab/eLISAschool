Three sibling feature packages (`programmes`, `specialites`, `competences`) follow an identical internal layout: a `components/` folder with list/detail pages and form modals, a `hooks/` folder containing React Query data-fetching hooks, and an `index.ts` barrel that re-exports public types, hooks, and components. The `programmes` feature is the most complex, defining its domain model in `types/programme.types.ts` (ProgrammePedagogique, ProgrammeMatiere, ProgrammeChapitre, RessourcePedagogique) and exposing CRUD + chapter management hooks via `use-programmes.ts`. Each hook module defines a local `*_KEYS` constant object that builds hierarchical query keys for React Query cache invalidation, and all mutations call `queryClient.invalidateQueries` on related keys after success. UI components are stateless page/modal React components that consume these hooks; there is no shared business logic between the three features, keeping them independent vertical slices.
