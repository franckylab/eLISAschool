Published as the `@elisaschool/shared` npm package (`package.json`, `main: dist/index.js`, `types: dist/index.d.ts`) and compiled with plain `tsc`. The barrel `src/index.ts` re-exports six orthogonal sub-packages:

- `enums/` — canonical enumerations: `ModuleName` + `ModuleCategory` + `MODULE_CATEGORIES` map (source of truth for every module key), `Role` (67 granular roles), `Permission` (~230 fine-grained permission strings), plus domain enums in `statuts.enum.ts` (request/document/notification/payment/status/gender).
- `config/config.registry.ts` — a large `MODULE_REGISTRY: Record<ModuleName, ModuleConfig>` object declaring each module's label, icon, basePath, premium flag, defaultRoles, permissions, dependencies and defaultSettings; accessor helpers `getModuleConfig`, `getModulesByCategory`, `hasModuleAccess` sit at the bottom.
- `constants/` — frozen app metadata, pagination/file/password limits, currencies (XOF/XAF/EUR/USD) and languages via `as const` objects.
- `types/` — cross-cutting interfaces `ApiResponse<T>`, `PaginatedResult<T>`, `PaginationOptions`, `ApiError`, plus user model `IUser` / `IUserProfile` / `IUserWithProfile` / `IUserSession` referencing the enums above.
- `validators/auth.validators.ts` — Zod schemas (`loginSchema`, `registerSchema`, …) using French field names and `LIMITS`; inferred `LoginInput` etc. are exported so backend and frontend share one validation contract.
- `helpers/system-protection.helper.ts` — `assertNotSystem` / `assertNotImmutable` guards that throw typed errors on entities flagged `estSysteme`, protecting seed data from deletion.

Dependency direction is strictly inward: config depends on enums, validators depend on constants, types depend on enums; nothing in this package imports any feature module. The `dist/` directory holds the compiled JS emitted by `npm run build`.
