Top-level `package.json` declares npm workspaces (`backend`, `frontend`, `shared`) so both clients resolve the same TypeScript types/validators from `shared_package`, enforcing a single source of truth for roles, permissions, module metadata and API contracts. The root also owns cross-cutting tooling: `docker_infra` (Compose files for dev/prod with PostgreSQL + Redis), `scripts_tooling` (bootstrap/migrate/seed/deploy scripts invoked through root `npm run` aliases like `db:migrate`, `docker:dev`, `build`), and French-language docs in `docs`. Children communicate only through the shared package's typed surface; there is no direct runtime coupling between backend and frontend at this level — the root merely coordinates builds, tests, migrations and container lifecycles across all three workspace packages.
