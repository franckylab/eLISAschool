Flat collection of executable entry-points grouped by lifecycle stage rather than layered packages:
- Lifecycle: `start-dev.sh` / `stop-dev.sh` orchestrate Docker services (PostgreSQL, Redis) via `docker-compose`, then launch `npm run dev` for backend (port 3001) and frontend (port 5173), writing PIDs under `/tmp/`.
- Database bootstrapping: `creer-base-de-donnees.sh` + `supprimer-base-de-donnees.sh` wrap `createdb`/`dropdb`; `deploy-complet.sh` chains DB creation, sequential `psql -f *.sql` migration execution over `database/migrations/*.sql`, TypeScript seeds via `ts-node -r tsconfig-paths/register src/database/seeds/run-seeds.ts`, and an optional `npm run build`.
- Per-module feature rollouts: every `deploy-*.sh` script targets a single domain (messagerie, organisation, scoring, recrutement, salons, permissions, RBAC v3, structure-academique, etc.) and is idempotent — they check existence before creating tables/rows so they can be re-run safely.
- Data fixes: `fix-*.sh` / `fix-*.sql` / `migrate-*.sh` patch existing installations in place (super-admin permissions, academic structure, multi-etablissement coherence).
- Tests: `test-*.sh` scripts hit live HTTP endpoints (`/api/health`, module routes) with `curl` against the running dev stack; `verify-*.sh` scripts assert file presence, import correctness, port availability, and DB connectivity.
- Helpers: small Node/Python utilities (`add-auth-to-hooks.js`, `analyse-permissions-manquantes.js`, `generate-fonds-svg.js`, `mark-obsolete.py`, `move-docs.py`) invoked from shell scripts or CI.
Dependency direction is one-way: scripts depend on the repo's `backend/`, `frontend/`, and `docker/` directories but are never imported by application code. The README documents the canonical workflow; `GUIDE-TEST-RAPIDE.md` focuses on the Finance module end-to-end smoke test.
