Single `docker/` directory is a self-contained deployment surface for the three-layer app (backend Express, frontend React/Vite, shared TS library) plus infra services. `docker-compose.yml` defines four containers — `postgres:16-alpine` on port 7002, `redis:7-alpine` on 7003, the backend built from `Dockerfile.backend.dev` (hot-reload via nodemon, bind-mounts `../backend`, `../shared`, `../public`) and the frontend from `node:20-alpine` running Vite dev server on 7001, plus `pgadmin4` on 7004 sharing the `elisaschool_network`. Two multi-stage production Dockerfiles exist: `Dockerfile.backend` builds `shared` then `backend` workspaces and runs as non-root user `expressjs`; `Dockerfile.frontend` produces an Nginx image serving static assets from `/usr/share/nginx/html` with `nginx.conf` reverse-proxying `/api` and `/ws` to the backend upstream. Environment is split by mode via four compose overlays (`docker-compose.{local,cloud}.{dev,prod}.yml`) selected by `deploy.sh`, which also auto-generates secrets in `.env.local` / `.env.cloud` (OpenSSL rand), validates minimum key lengths for prod, detects host IP for CORS, and wraps `docker compose up|down|rebuild|status|logs`. Backup/restore lives under `scripts/`: `backup-auto.sh` classifies daily/weekly/monthly snapshots by date and rotates them via `find -mtime`, `restore.sh` performs integrity checks, creates a safety backup before overwriting, and verifies post-restore row counts; cron entry is provided by `cron-backup.txt` + `install-cron.sh`. `init-scripts/` seeds the DB at first container start, and `pgadmin-servers.json` pre-configures the pgAdmin connection.
