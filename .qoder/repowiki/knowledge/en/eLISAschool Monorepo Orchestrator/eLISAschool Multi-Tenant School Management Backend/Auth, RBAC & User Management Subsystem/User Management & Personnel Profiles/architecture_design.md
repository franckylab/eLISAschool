Layered Express module under `backend/src/modules/utilisateurs/` with a strict controller → service → TypeORM repository flow:
- `controllers/` — one Express Router per sub-domain (`utilisateurs.controller.ts`, `upload.controller.ts`) mounted at `/api/utilisateurs`; every route is guarded by `authMiddleware` + `requirePermission('utilisateurs:*')` from `@modules/auth/middlewares`.
- `services/` — business logic isolated in classes (`UtilisateursService`, `UploadService`, `VerificationSuppressionService`). `UtilisateursService` owns repositories for `Utilisateur`, `ProfilUtilisateur`, `Role`, `Permission`, `UtilisateurPermission`, `UtilisateurEtablissement` (all fetched via `AppDataSource.getRepository(...)`) and performs RBAC v3 permission computation (`computeEffectivePermissions` merges role permissions with direct GRANTED/DENIED entries).
- `dto/` — Zod schemas (`createUtilisateurSchema`, `updateUtilisateurSchema`, `queryUtilisateursSchema`, …) validated at the controller boundary via `validateDto` before reaching the service; response shape is defined by the `UtilisateurResponseDto` interface.
- `entities/` — re-exports only `Utilisateur` from `@modules/auth/entities/utilisateur.entity`, keeping this module entity-free and dependent on the auth module rather than vice-versa.
- Cross-module dependencies: reads `MembrePersonnel` / `TypePersonnel` from `@modules/personnel/entities`, calls `tokenService.revokeAllUserTokens` and `auditService.log` from `@modules/auth`, and delegates establishment-role toggling to `utilisateurEtablissementService`. The `verification-suppression.service.ts` provides pre-delete impact checks consumed by both soft and cascade delete routes.
- Pagination uses the shared `@common/utils/pagination.util` (`paginateWithQueryBuilder`) with an optimized COUNT path for JOIN-heavy queries.
