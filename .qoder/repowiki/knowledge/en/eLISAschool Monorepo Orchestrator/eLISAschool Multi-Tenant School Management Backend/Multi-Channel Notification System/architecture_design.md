Layered Express module exposing REST routes under `/api/notifications` (`controllers/`) backed by a `NotificationsService` (`services/notifications.service.ts`) that owns the TypeORM `Notification` entity (`entities/notification.entity.ts`). Delivery is decoupled via an interface-driven provider pattern: `INotificationProvider` in `providers/interfaces/` defines `envoyer`, `initialiser`, `estConfiguré`, optional `getQuota`; concrete implementations live in `providers/*.ts` (Email/Nodemailer, SMS/Twilio, Push/Firebase, In-App). A singleton `ProviderRegistry` (`providers/provider-registry.ts`) maintains per-type provider lists and implements automatic fallback across configured providers. Runtime behaviour is driven by centralised config keys (`notifications.enable_*`, `notifications.default_channel`) read through `getParamBoolean`/`getParam`. Cron jobs in `cron-jobs.ts` (node-cron, timezone `Africa/Lome`) drive three periodic tasks: daily canteen payment reminders, nightly cleanup, and every-5-min processing of `programmeePour`-scheduled notifications. DTOs in `dto/` are validated against zod schemas before reaching controllers; audit events are emitted to `@modules/auth`'s `auditService`. The module root re-exports entities/dto/services/controllers for other modules to consume.
