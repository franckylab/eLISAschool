Express-style module split into `entities/` (TypeORM models), `services/`, `controllers/`, `dto/` plus a top-level `cron-jobs.ts`. Three domain entities are defined: `IncidentPersonnel` (disciplinary events with severity/status enums), `EvaluationPersonnel` (periodic reviews linked to `AnneeScolaire`/`Periode`), and the scoring triad `ScorePersonnel` + `RegleScoringPersonnel` + `HistoriqueScorePersonnel` that aggregates points across categories (assiduité, comportement, performance, pédagogie) and records every delta. The singleton `ScoringPersonnelService` owns all business logic — point attribution, source-data-driven recalculation (`recalculerScore` reads incidents/absences/evaluations in parallel), weighted global score computation, ranking queries, and rule CRUD with an in-process LRU cache keyed by `etablissementId`. Controllers expose REST endpoints under `/api/scoring-personnel/*` guarded by `authMiddleware` + `requirePermission('config:edit')`, delegating to the service and using Zod schemas from `dto/` for validation. `cron-jobs.ts` registers four `node-cron` schedules (daily recalc at 23:30, midnight ranking update, monthly reset, weekly history cleanup) gated by feature flags read via `getParamBoolean('scoring-personnel.*')` from the configuration module; a manual `runScoringRecalculManual` entrypoint is also exposed through a super-admin endpoint. Cross-module dependencies flow one-way: this module depends on `@modules/personnel/entities` (MembrePersonnel, AbsencePersonnel, TypePersonnel), `@modules/auth/entities`, `@modules/etablissement/entities`, `@modules/annees-scolaires/entities`, `@modules/periodes/entities`, `@modules/matieres/entities`, `@modules/classes/entities`; nothing inside this module is imported back by those peers except via the barrel `index.ts` re-exports.
