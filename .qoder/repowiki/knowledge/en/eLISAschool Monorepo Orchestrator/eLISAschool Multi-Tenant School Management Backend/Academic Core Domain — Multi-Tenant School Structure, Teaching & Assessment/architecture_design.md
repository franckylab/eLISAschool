Each sub-module follows an identical NestJS barrel pattern: `index.ts` re-exports `entities`, `dto`, `services`, and `controllers`, so consumers import from `@/modules/<name>` without knowing internal folders. Cross-child relationships are expressed purely through TypeORM entity foreign keys rather than service calls — e.g. `matiere.entity.ts` references `niveau`, `programme-matiere` links `matiere` to `programme-pedagogique`, `periode` is bound to `annee-scolaire`, and `competence`/`evaluation-competence` feed into `examen-national`. The `etablissement` entity anchors every other table via a `etablissementId` column, enforcing multi-tenancy at the ORM level; no shared repository or base class is used between children. Higher-level modules (personnel, evaluation, planning) depend on this package as their canonical source of truth for the academic hierarchy.
