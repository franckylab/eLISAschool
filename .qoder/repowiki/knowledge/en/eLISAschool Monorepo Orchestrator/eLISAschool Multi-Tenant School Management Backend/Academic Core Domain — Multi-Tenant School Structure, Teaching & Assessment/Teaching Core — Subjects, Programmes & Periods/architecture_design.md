Three sibling Nest/Express sub-modules sharing the same internal layout (`entities` / `dto` / `services` / `controllers` + barrel `index.ts`).

- `matieres`: defines `GroupeMatiere`, `Matiere`, `MatiereNiveau`, `AffectationMatiere`, `ConfigurationMatiereClasse` entities; a single `MatieresService` exposes CRUD plus the 'grille matière par niveau' resource and teacher assignment APIs; one Express router mounts all routes under `/matieres`.
- `programmes`: models the curriculum tree — `ProgrammePedagogique` (scoped by `etablissementId`, optional `cycleId`/`niveauId`, linked to a `Periode` and `AnneeScolaire`) owns `ProgrammeMatiere` entries which in turn own `ProgrammeChapitre`s. A dedicated `correlation-programme.service` handles programme-to-programme correlations. The module's `index.ts` builds an Express Router that mounts four child routers (`/chapitres`, `/correlation`, `/matieres`, `/`) so other modules can import `programmesController` as a mounted subtree.
- `periodes`: v5.0 replaces the old `TypePeriode` enum with a FK to `NiveauPeriode` so each establishment configures its own hierarchy levels; `PeriodeComposition` is the sole parent-child join table supporting arbitrary depth. `PeriodesService.findAllArbre` builds the full tree in one pass via a `Map` of loaded nodes rather than recursive DB queries.

Cross-module dependencies: `programmes` depends on `@modules/periodes/entities` (a `ProgrammePedagogique` links to a `Periode`); `periodes` imports `StatutNote` from `@modules/notes`. All three modules are multi-tenant through an `etablissementId` column present on every entity and enforced at query time by passing `etablissementId` from `req.utilisateur.etablissementId` into service calls. Services resolve cross-module collaborators lazily via `await import(...)` (e.g. `annees-scolaires/services`, `niveaux-periode.service`) to avoid circular bootstrap.
