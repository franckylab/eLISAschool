Standard three-layer Nest-style layout under `backend/src/modules/paie/`:
- `entities/` — TypeORM definitions (`BulletinPaie`, `ElementSalaire`, `Cotisation`, `TypePrime`, `TypeRetenue`) all scoped per `etablissementId` with cascade deletes; enums model the domain state machine (`StatutBulletinPaie`, `TypeCotisation`, `TypeElementSalaire`, …).
- `services/` — pure business logic. `CalculPaieService` is the core: it reads the active `ContratPersonnel`, dispatches on `modeRemuneration` (MENSUEL/HORAIRE/MIXTE/HEBDOMADAIRE), pulls hours via `@modules/personnel/services.heureCoursService`, applies `TypePrime` and `Cotisation` tables, then persists a `BulletinPaie` plus its `ElementSalaire` detail rows. It also triggers the cross-module `validationWorkflowService` and `auditService`.
- `controllers/` — thin Express routers exposing REST endpoints (`POST /generer/:membreId`, `/rapport-comptable`, nested `/:id/elements` CRUD). Each route chains `authMiddleware` + `requirePermission('paie:*')` + `validateDto(schema)` before delegating to the service.
- `dto/` — Joi schemas consumed by `validateDto`.
Dependency direction is strictly controllers → services → entities, with cross-module imports only into `personnel`, `etablissement`, `auth`, `configuration`, and `validation-workflow`. The module re-exports everything through `index.ts` so other modules import from `@modules/paie`.
