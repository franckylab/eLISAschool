Each sub-directory under `backend/src/modules/` is an independent NestJS module following a consistent vertical slice layout — `controllers/`, `dto/`, `entities/`, `services/`, plus optional `middlewares/` — re-exported through a per-module `index.ts`. Cross-cutting concerns are isolated in sibling modules (`@modules/responsables-eleves/middlewares/parent-access.guard.ts` provides `requireParentAccess` / `requireParentPaymentAccess` Express middleware that delegates to `parentsService.peutAccederEleve`); other modules consume it via the standard Express pipeline. Entities are plain TypeORM classes with UUID primary keys, `@Index` annotations on hot lookup columns, and `simple-json` columns for flexible payloads (e.g. allergies, documents). Business logic lives in services; controllers stay thin. The `notes` module adds a dedicated `NotesBatchLoaderService` singleton that coalesces N+1 average calculations into single SQL queries grouped by period, with an in-process LRU-style cache keyed by `(periodeId, sorted eleveIds, sorted matiereIds)` and a 5-minute TTL. Multi-tenancy is enforced at the entity level via an `etablissementId` foreign key present on core entities like `Eleve`. Workflow state is modelled as separate entities (e.g. `BulletinWorkflow` with its own `StatutValidationBulletin` enum) rather than ad-hoc status fields.
