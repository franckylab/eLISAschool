Two sibling Nest-style modules under `backend/src/modules/`, each following the same layered pattern: `entities/` (TypeORM models), `dto/` (validation schemas), `services/` (business logic with direct TypeORM repository access via `AppDataSource.getRepository`), `controllers/` (Express routers exposing REST endpoints), plus an `index.ts` barrel re-exporting all layers.

- **gamification/**: Models (`Badge`, `PointsUtilisateur`, `HistoriquePoints`, `BadgeUtilisateur`) track user points, badges, and history. `GamificationService` reads point values from the centralized configuration module (`getParamNumber`/`getParamBoolean`). A separate `cron-jobs.ts` registers four `node-cron` tasks (daily attendance points, weekly/monthly resets, automatic badge checks) using the `Africa/Douala` timezone.
- **scoring/**: Split into `ConfigurationScoring` (per-establishment/year grading policy: calculation method, grading scale, coefficients, mentions, auto-appreciations) and `Scoring` (student scores, history, rules). `ConfigurationScoringService` enforces uniqueness by establishment+year and resolves active config with year-specific > global fallback. `ScoringService` computes weighted global scores from four indicator types (`ACADEMIQUE`, `COMPORTEMENT`, `ASSIDUITE`, `PARTICIPATION`) using configurable weights.

Dependency direction is strictly one-way: controllers → services → TypeORM repositories; both services depend on `@modules/configuration/utils/config.helper` for runtime parameters and on shared entities like `Utilisateur`, `Etablissement`, `AnneeScolaire`. Cron jobs depend on services but not on controllers.
