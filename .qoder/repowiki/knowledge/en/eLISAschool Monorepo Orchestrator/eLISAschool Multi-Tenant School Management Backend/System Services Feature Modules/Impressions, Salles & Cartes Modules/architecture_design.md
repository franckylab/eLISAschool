Each sub-folder (`impressions/`, `salles/`, `cartes/`) is a self-contained NestJS module following the standard layered layout: `entities/` (TypeORM `@Entity` classes with UUID PKs, `@Index` annotations, multi-tenancy via `etablissementId`), `dto/` (Zod schemas paired with `z.infer` types), `services/` (business logic exposing plain async methods), `controllers/` (HTTP endpoints re-exported through barrel `index.ts` files), and a root `index.ts` that re-exports all layers for consumers.

- `impressions`: defines `ModeleDocument` (HTML template + header/footer/style JSON) and `FileImpression` (print queue with `StatutImpression` state machine); DTOs validate template creation and print requests.
- `salles`: `Salle` entity models rooms with `TypeSalle`/`StatutSalle` enums; `SalleAvailabilityService` composes cross-module reads from `@modules/emploi-du-temps/entities.EmploiDuTemps` and `@modules/personnel.entities.HeureCours` to compute conflicts over both weekly schedules and per-day `HeureCours`, returning a unified `ConflitSalle[]` discriminated by `source`.
- `cartes`: `Carte` ↔ `ModeleCarte` (card template with dimensions, colors, displayed fields, HTML template) linked via optional `modeleCarteId`; `GenerationBatchService` performs bulk generation per class or personnel using dynamic `import()` to avoid circular deps on `@modules/eleves` and `@modules/personnel`, falling back to default active model when none is supplied.

Dependency direction is strictly inward: these three modules depend on shared modules (`@modules/auth`, `@modules/etablissement`, `@modules/emploi-du-temps`, `@modules/personnel`, `@common/*`) but are not depended on by them. Cross-module access is done at runtime via lazy `import()` inside services rather than static imports, preventing circular initialization.
