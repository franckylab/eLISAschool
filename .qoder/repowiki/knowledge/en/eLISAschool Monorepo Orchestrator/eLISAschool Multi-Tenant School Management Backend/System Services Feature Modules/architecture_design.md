Each child under `backend/src/modules/` is a standalone NestJS-style feature module exposing its own `index.ts` barrel plus controllers/dto/entities/services/guards/middlewares — there is no cross-module orchestration layer here. Cross-cutting concerns are handled by individual modules importing from shared infrastructure outside this scope (e.g. `@modules/configuration` provides a pluggable storage provider interface used by backup; `@modules/validation-workflow` is consumed by other modules via its service API). The only structural coupling within this scope is that some modules depend on the configuration store (`parametre-systeme`, `configuration-app`) for runtime toggles and enum catalogs (`type-enum`). There is no parent-level wiring, DI container, or shared base class across children — they are registered independently by the application bootstrap.
