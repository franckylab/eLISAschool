Three cooperating layers form the runtime contract:
- `src/app` (app shell) instantiates React context providers, QueryClient, i18n, theme stores and mounts the route tree — it is the sole owner of cross-cutting concerns.
- `src/features/<domain>` packages each business area as an isolated package (`components/`, `hooks/`, `types/`, `index.ts`) that exposes typed hooks and page components; features never import sibling features directly, communicating only through shared hooks/stores in `src/hooks` and `src/stores`.
- `src/routes/*` registers every page via TanStack Router's file-based convention, grouping authenticated routes under `_auth.*` barrel files (infrastructure, pedagogical, RH, vie scolaire, etc.) which are then mounted by the shell's generated route tree.

Cross-cutting enforcement at this level: all API calls flow through `src/lib/api-client.ts` / `api.ts` (TanStack Query-backed), all user-facing text comes from `locales/{fr,en}/*.json` loaded by `lib/i18n.ts`, and every feature must re-export its public surface from its own `index.ts` barrel so route barrels can import pages without knowing internal paths. Build-time assets (favicons, icons) live in `public/` and are generated by scripts in `scripts/`. The current refactoring effort targets the Organisation module to remove the Organisation entity (merged into Etablissement), revise enums, attach units directly to establishments, simplify the frontend, and introduce Cameroonian-context presets.
