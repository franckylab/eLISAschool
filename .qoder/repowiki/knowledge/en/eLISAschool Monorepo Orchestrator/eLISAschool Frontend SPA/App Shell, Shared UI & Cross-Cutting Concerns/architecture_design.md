The module is organized as a flat set of cross-cutting concerns consumed by feature pages:
- `app/` — Application root (`App.tsx`) creates the TanStack Router instance from the generated `routeTree.gen`, wraps everything in `ErrorBoundary`, initializes theme and auth on mount, and conditionally mounts a dev-only `DebugPermissions` panel. `providers.tsx` composes `QueryClientProvider` (from `@tanstack/react-query`) and a themed `Toaster`. `permission-guards.ts` and `route-guards.ts` are pure functions that read `useAuthStore.getState()` and throw `redirect(...)` for use in route `beforeLoad` hooks.
- `stores/` — Zustand stores (`auth.store`, `theme.store`, `language.store`, `sidebar.store`) exposed via a barrel `index.ts`; they are the single source of truth for auth state, theme, language, and sidebar visibility.
- `hooks/` — Reusable composition hooks grouped by concern: auth/session (`use-auth`, `use-session-expired`, `use-multi-tenant`), permissions (`use-permissions`, `use-permissions-advanced`, `use-sensitive-tabs`), UI helpers (`use-modal-window`, `use-confirm`, `use-breakpoint`, `use-media-query`, `use-debounce`, `use-document-title`, `useTabState`), and domain-specific ones (`use-etablissement-selection`, `use-dashboard-widgets`, `use-datatable-preferences`). All re-exported from `hooks/index.ts`.
- `components/` — Layered component hierarchy: `ui/` holds low-level primitives (buttons, inputs, cards, badges, tabs, search/filter panels) with their own barrel; higher-level domain components live in sibling folders (`auth/`, `layout/`, `feedback/`, `modals/`, `permissions/`, `charts/`, `branding/`, `navigation/`). Each folder also ships an `index.ts` barrel.
- `lib/` — Framework-agnostic utilities (`cn`, `date-utils`, `format-utils`, `theme-utils`, `i18n`, `api-client`, `api`, `query-client`, `secure-logout`) re-exported through `lib/index.ts`.
- `styles/globals.css` — Global CSS variables and Tailwind base layer.

Dependency direction is strictly inward: `app` → `stores` + `components` + `lib`; `components` → `hooks` + `stores` + `lib`; `hooks` → `stores` + `lib`; `lib` has no internal dependencies. Feature routes outside this scope import only from these barrels.
