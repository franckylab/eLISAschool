Two sibling concerns are grouped here:
- `src/routes/` declares every page via TanStack Router's file convention. `_auth.tsx` is the authenticated layout root (beforeLoad: authGuard, shared PageLayout, session-expiry listener, global Etablissement modal); all feature routes under it inherit these guards. Public pages (`login`, `forgot-password`, `reset-password`, `verify-email`) sit at the routes root without the `_auth` prefix. Feature modules follow two patterns: flat per-file routes (`_auth.eleves.tsx`, `_auth.admin.roles.tsx`) for simple features, and grouped subdirectories with a `route.tsx` entry plus sibling feature files (e.g. `(authenticated)/parametres/structure-academique/`) for nested sections. `- _auth.*.tsx` placeholder files silence router warnings while keeping related routes co-located. Module-level permission checks live in each route's `beforeLoad` hook, gated through the shared `@/app/route-guards` module.
- `src/locales/{fr,en}/` holds one JSON bundle per domain feature (e.g. `eleves.json`, `notes.json`, `utilisateurs.json`). The filename-to-feature mapping mirrors the route naming so any route can import its corresponding locale pack through the shared i18n runtime used elsewhere in the app.
The two directories are coupled by naming: a route like `_auth.eleves.tsx` corresponds to `locales/fr/eleves.json` and `locales/en/eleves.json`, keeping UI strings and their owning page colocated across languages.
