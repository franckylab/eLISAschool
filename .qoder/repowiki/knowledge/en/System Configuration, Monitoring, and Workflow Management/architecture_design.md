- **Configuration Module**: Acts as the core system backbone, implementing a hybrid storage strategy (global vs. tenant-scoped) with an in-memory caching layer (`ConfigCache`) and an event-driven architecture (`ConfigurationListener`) to notify other modules of changes. It features a pluggable storage provider interface (`IBackupStorage`) for configuration and database backups, currently implemented via `DatabaseStorageProvider`.
- **Validation Workflow Module**: Implements a generic, multi-level approval engine reusable across various business domains (e.g., grades, bulletins). It uses a custom middleware (`requireValidationLevel`) that integrates with a permission resolver service to enforce role-based validation steps.
- **Monitoring & Audit Modules**: Provide system health checks, metric collection, and comprehensive audit trail management. The audit module includes an archiving service for log retention and supports CSV/JSON exports.
- **Support Modules**: `types-enum` manages customizable enumeration types with system/custom distinctions; `requetes` handles user support tickets; `impressions` manages a print queue and document template generation.
- **Interface Boundaries**: All modules expose RESTful controllers protected by RBAC guards (`requireRoles`, `canEditConfigApp`, etc.) and use DTOs for input validation.
