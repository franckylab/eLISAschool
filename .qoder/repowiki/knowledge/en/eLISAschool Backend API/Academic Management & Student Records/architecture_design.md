- Each of the 9 sub-modules (annees-scolaires, cycles, niveaux, periodes, matieres, eleves, notes, bulletins, orientation) follows a strict four-layer internal structure: controllers → services → entities + DTOs, with each layer exported via index.ts barrel files.
- Controllers use Express Router instances with inline Zod validation via a shared `validate<T>` helper that throws `AppError` on schema failure; every route handler wraps async logic in try/catch forwarding to Express error middleware.
- Services are plain TypeScript classes that obtain TypeORM repositories from a shared `AppDataSource`; they encapsulate business rules (e.g., deactivating previous active school years, preventing duplicate matricules, computing weighted averages for report cards).
- Entities are TypeORM-decorated classes mapped to PostgreSQL tables, using UUID primary keys, `@CreateDateColumn`/`@UpdateDateColumn` timestamps, and cross-module relations via `@ManyToOne` with explicit `@JoinColumn` foreign keys.
- DTOs are Zod schemas defining create/update/query contracts; types are inferred via `z.infer`, ensuring runtime validation parity with compile-time types.
- Cross-module dependencies flow through service imports (e.g., bulletins.service imports classesService, periodesService, notesService, matieresService), establishing a directed acyclic graph where higher-level modules depend on foundational ones.
- Role-based access control is enforced at the controller layer via `authMiddleware` and `requireRoles(Role.*)`, with roles such as ADMIN, SUPER_ADMIN, ENSEIGNANT, CHEF_ETABLISSEMENT gating write operations.
