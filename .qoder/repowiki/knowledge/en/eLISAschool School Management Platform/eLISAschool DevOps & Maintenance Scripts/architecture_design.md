Flat directory of executable entry points grouped by lifecycle stage rather than layered packages:
- Development: `start-dev.sh` / `stop-dev.sh` orchestrate Docker (PostgreSQL, Redis), Node backends (`npm run dev`) and Vite frontend, writing PIDs under `/tmp/elisaschool-*.pid` and polling `/api/health`.
- Deployment: `deploy-complet.sh` is the canonical one-shot installer — it probes Docker/psql, creates the DB via `createdb` or `psql`, runs every `backend/database/migrations/*.sql` in sorted order, then executes `ts-node -r tsconfig-paths/register src/database/seeds/run-seeds.ts` before an optional `npm run build`. Per-module rollouts live in `deploy-*.sh` files (organisation, messagerie, scoring, structure-academique, etc.) that target a single feature area.
- Database ops: `creer-base-de-donnees.sh`, `supprimer-base-de-donnees.sh`, `run-migration-NNN.sh`, `run-rh-migrations.sh`, `run-scoring-sql-migration.sh`, plus ad-hoc SQL fixes (`fix-super-admin-permissions.sql`).
- Verification & tests: `verify-*.sh` scripts assert environment health (ports, services, imports); `test-*.sh` scripts hit running endpoints with curl; `validate-architecture-v2.sh` enforces structural rules.
- Auth & permissions tooling: JS helpers (`add-auth-to-hooks.js`, `analyse-permissions-manquantes.js`, `check-permissions.js`, `migrate-require-roles-to-permission.js`, `fix-missing-isauthenticated.js`) operate on backend source trees to propagate authentication guards and role checks.
- Misc automation: Python docs/index generators (`mark-obsolete.py`, `move-docs.py`, `reclassify-autres.py`, `update-docs-index.py`), SVG background generator (`generate-fonds-svg.{js,sh}`), network/Docker bootstrap (`config-reseau-local.sh`, `rebuild-docker.sh`).
Dependency direction is outward-only: scripts call external binaries (`docker`, `psql`, `curl`, `npm`, `npx ts-node`, `lsof`) and read/write project-relative paths; there are no shared libraries inside this folder.
