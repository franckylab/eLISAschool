Top-level orchestration is purely structural: `backend/` (Express + TypeORM), `frontend/` (React + Vite PWA), `shared/` (cross-cutting Zod validators and TS types consumed by both sides), `docker/` (compose stack for Postgres + Redis), and `scripts/` (devops utilities invoked from root). The children communicate exclusively through the REST API surface; there is no runtime parent process. Root-level docs (`README.md`, `QUICKSTART.md`, `INDEX.md`, `CHEATSHEET.md`, `AGENTS.md`) act as entry points that delegate to the `docs/` archive, while `.gitignore` and `.dockerignore` apply repo-wide exclusion rules. Current change-period intents centre on two cross-module refactors — collapsing Organisation into Etablissement and clarifying the orthogonal TypePersonnel/Fonction relationship — which touch both backend entities and their corresponding frontend features.
