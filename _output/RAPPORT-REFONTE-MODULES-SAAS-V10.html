CRITIQUE → BASE : Justification

Recherche web — Meilleures pratiques SaaS : Les leaders du marché (Stripe, HubSpot, Slack, Shopify) utilisent tous des terminologie positives pour leurs tiers de base. "CRITIQUE" a une connotation d'urgence/négativité qui est contre-productive dans un contexte commercial.
TermeExemples marchéConnotationVerdict
BASEHubSpot (Free), Slack (Free)Neutre, fondation, universel✅ Recommandé
ESSENTIELShopify (Basic)Positif, nécessaireAlternative
FONDATION—Structurel, solideTrop long
COREStripe (Core)Technique, centralAnglicisme
SYSTÈME—TechniqueConfus avec OS
GRATUITSlack (Free)CommercialPas toujours gratuit
Décision : BASE est retenu. Le terme est court (4 lettres), universellement compris, neutre, et aligné avec les standards SaaS. Il s'oppose naturellement à PREMIUM et ADDON.

Phases d'implémentation

Phase P1 — CRITIQUE → BASE (Backend + Frontend)

Renommage de l'enum CategorieModule et de toutes les références dans le codebase. Migration SQL des données existantes.

Fichiers : module-catalogue.entity.ts modules.enum.ts entitlement.service.ts configuration.service.ts marketplace.controller.ts seed-modules-catalogue.ts _auth.marketplace.tsx platform.modules.tsx module-toggle-card.tsx fr/admin.json en/admin.json Migration SQL
Impact: Élevé Risque: Moyen ~15 fichiers

Phase P2 — Modules → Marché / Marketplace

Renommage du label "Modules" en "Marché" (FR) et "Marketplace" (EN) dans la sidebar tenant. La plateforme conserve "Catalogue modules".

Fichiers : Sidebar.tsx fr/common.json en/common.json fr/admin.json en/admin.json
Impact: Faible Risque: Faible ~5 fichiers

Phase P3 — Menu "Mon Établissement"

Création du groupe "Mon Établissement" dans la sidebar avec 7 sous-menus. Déplacement des items existants (Établissements, Groupes, Modules, Mon Abonnement).

Fichiers : Sidebar.tsx fr/common.json en/common.json Nouvelles routes si nécessaire
Impact: Moyen Risque: Faible ~5 fichiers

Phase P4 — Refonte pages billing

Refonte de la page "Mon Abonnement" (3 onglets cibles), extraction du simulateur vers "Plans d'abonnement", création route /plans-abonnement, nettoyage des redondances.

Fichiers : _auth.mon-abonnement.tsx _auth.factures.tsx Nouveau: _auth.plans-abonnement.tsx Nouveau: _auth.usage-quota.tsx (ou réutiliser existant) _auth.facturation.tsx (redirect à mettre à jour)
Impact: Élevé Risque: Moyen ~6 fichiers

Phase P5 — Polish plateforme + Documentation

Alignement de la plateforme (Control Plane) : "Catalogue modules" (pas "Marché"), mise à jour AGENTS.md, règles, et skills.

Fichiers : platform-sidebar.tsx platform.modules.tsx AGENTS.md elisaschool-conventions.md
Impact: Faible Risque: Faible ~5 fichiers

Matrice d'impact

Ordre d'exécution : P1 (CRITIQUE→BASE) est la fondation — tous les autres phases dépendent de ce renommage. P2 et P3 sont des changements UI indépendants. P4 est le plus complexe (refonte pages). P5 est le polish final.
