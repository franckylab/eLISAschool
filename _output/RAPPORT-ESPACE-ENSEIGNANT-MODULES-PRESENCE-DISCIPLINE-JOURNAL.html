Ce rapport présente l'analyse approfondie et la conception architecturale de trois nouveaux modules pour eLISAschool : Présence, Discipline et Journal de Classe. Ces modules forment le socle de l'Espace Enseignant complet.

🎯 Objectif stratégique : Offrir aux enseignants un espace numérique de travail complet, intégré et modulaire, permettant la gestion quotidienne de leurs cours (appel, discipline, journal) tout en enrichissant automatiquement le dossier scolaire de l'élève et le scoring existant.

Principes Directeurs

🧩 Autonomie

Chaque module est désactivable/réactivable sans impact sur le fonctionnement global. Isolation complète via modules_catalogue.

🔗 Intégration

Les modules s'appuient sur HeureCours comme point d'ancrage commun et enrichissent le Scoring, les Bulletins et le Suivi Élèves.

🌍 Multi-Tenant

Isolation stricte par etablissementId, RLS PostgreSQL, et paramètres configurables par établissement via ParametreSysteme.

2.2 Entité Pivot — HeureCours

💡 Point clé : HeureCours est l'instance concrète d'un cours à une date précise. C'est le point d'ancrage naturel pour la Présence (appel des élèves du cours) et le Journal de Classe (contenu du cours effectué).

2.3 Lacunes Identifiées

❌ Présence des élèves

Les types d'absence existent dans le frontend mais aucun module backend ne permet l'appel systématique par cours. Le scoring mentionne l'ASSIDUITÉ mais n'a pas de source de données.

❌ Journal de classe

Aucun cahier de texte numérique. Les enseignants n'ont pas d'outil pour tracer les contenus enseignés, les devoirs donnés ou les ressources partagées.

⚠️ Discipline contextuelle

Le module suivi-eleves gère les incidents mais sans lien direct au cours. Un incident pendant un cours spécifique n'est pas contextualisé (matière, heure, présence).

❌ Espace enseignant unifié

Pas de portail dédié à l'enseignant regroupant ses cours du jour, les appels à faire, les journaux à remplir et les incidents à signaler.

3.2 Meilleures Pratiques Identifiées

📱 Multi-modalité de l'appel

Pratique : Combiner 3 méthodes d'appel — manuel (liste), QR code (scan carte élève), et automatique (géofencing/NFC pour les grands campus).

Choix eLISAschool : Manuel + QR code

⚡ Appel rapide (< 2 min)

Pratique : L'appel ne doit pas dépasser 2 minutes. Présélection "tous présents", l'enseignant signale uniquement les absents/retards.

Choix eLISAschool : Default PRÉSENT + exceptions

🔔 Notification instantanée

Pratique : Alertes SMS/push aux parents dans les 15 minutes suivant l'absence constatée. Réduction du décrochage scolaire de 30%.

Choix eLISAschool : Via NotificationOrchestrator

📊 Analytics comportementaux

Pratique : Tableaux de bord par classe/matière/période avec indicateurs : taux d'absence, récidivistes, patterns temporels.

Choix eLISAschool : Intégré au Scoring

📝 Cahier de texte structuré

Pratique : Contenu pédagogique par séance : objectifs, déroulement, devoirs, ressources. Visible par les élèves et parents en consultation.

Choix eLISAschool : Lié à HeureCours

🎯 Discipline contextuelle

Pratique : L'incident est toujours contextualisé (cours, matière, heure) pour permettre une analyse fine et un suivi cohérent.

Choix eLISAschool : Extension suivi-eleves

3.3 Standards du Contexte Africain/Camerounais

⚠️ Adaptations nécessaires : Le contexte camerounais impose des spécificités :
  • Effectifs importants : classes de 60-120 élèves → appel rapide obligatoire
  • Connectivité limitée : mode hors-ligne + synchronisation différée
  • Saisons rurales : type d'absence "abandon temporaire" (récoltes)
  • Frais de scolarité : lien présence ↔ paiement frais
  • Uniforme obligatoire : type d'incident "tenue non conforme"

Mode Manuel (défaut)

Enseignant voit la liste complète des élèves de la classe. Par défaut tous marqués "PRÉSENT". Il clique sur les élèves absents/retards pour changer le statut.

Avantage : Simple, rapide, pas de matériel requis.

Mode QR Code

Chaque élève a un QR code sur sa carte scolaire. L'enseignant scanne les cartes au début du cours. Les élèves non-scannés sont marqués absents.

Avantage : Traçabilité, rapidité pour grands effectifs.

Notifications Parents

Dès la clôture de l'appel, les parents des élèves absents/retards reçoivent une notification (push, SMS, email) via le NotificationOrchestrator.

Avantage : Transparence, réduction absentéisme.

Intégration Scoring (non bloquant) try { for (const presence of presences) { if (presence.statut === StatutPresence.PRESENT) { await scoringService.attribuerPoints( presence.eleveId, TypeIndicateur.ASSIDUITE, +2 ); } else if (presence.statut === StatutPresence.RETARD) { await scoringService.attribuerPoints( presence.eleveId, TypeIndicateur.ASSIDUITE, -1 ); } else if (presence.statut === StatutPresence.ABSENT) { await scoringService.attribuerPoints( presence.eleveId, TypeIndicateur.ASSIDUITE, -3 ); } } } catch (e) { logger.warn('[Présence] Scoring échec (non bloquant)', e); } // 3. 6. Module Discipline — Conception Détaillée

6.1 Positionnement — Extension de suivi-eleves

💡 Décision architecturale : Le module Discipline ne remplace PAS suivi-eleves. Il l'enrichit avec un contexte cours. Un IncidentCours peut être "promu" en IncidentEleve si la gravité le justifie (workflow de escalation).

IncidentCours (léger)

Incident pendant un cours spécifique. Types : bavardage, téléphone, non-respect, retard, travail non fait. Gravités : MINEUR, MODERE. Résolu directement par l'enseignant.

Escalade vers IncidentEleve

Si gravité GRAVE/TRES_GRAVE ou récidive → l'incident est escaladé vers suivi-eleves pour traitement par la direction avec sanctions potentielles.

Points Comportement

Système de crédits/débits comportement. Solde initial 100. Actions positives (+), négatives (-). Seuil d'alerte configurable. Intégré au scoring COMPORTEMENT.

7. Module Journal de Classe — Conception Détaillée

7.1 Concept — Cahier de Texte Numérique

Le journal de classe est le pendant numérique du cahier de texte papier. Il permet à l'enseignant de tracer le contenu de chaque séance et de communiquer les devoirs aux élèves et parents.

📝 Contenu de séance

Pour chaque cours effectué, l'enseignant saisit : titre, objectifs, contenu déroulé, méthodologie, observations. Lié directement à HeureCours.

📚 Devoirs & travaux

Devoirs donnés avec date limite, description, pièces jointes. Visible par les élèves dans leur espace. Rappels automatiques avant échéance.

📎 Ressources partagées

Documents, liens, vidéos partagés avec la classe. Stockage via le module médias existant ou upload direct.

📊 Progression pédagogique

Suivi de l'avancement du programme par matière et par classe. Pourcentage complété, chapitres traités, estimation date de fin.

11. Conclusion & Recommandations

11.1 Synthèse

✅ Faisabilité confirmée : Les 3 modules (Présence, Discipline, Journal de Classe) sont parfaitement intégrables dans l'architecture existante d'eLISAschool. Le pivot HeureCours fournit le point d'ancrage naturel, et le système de modules_catalogue garantit l'autonomie (désactivation sans impact).

11.2 Recommandations Stratégiques

1. Prioriser la Présence

Module à plus fort impact immédiat. Réduction absentéisme + valorisation scoring + notification parents. ROI rapide visible.

2. UX avant fonctionnalités

Enseignants = utilisateurs pressés. Chaque action doit se faire en 3 clics maximum. Mode "appel rapide" par défaut (2 min max).

3. Mode hors-ligne PWA

Contexte africain = connectivité variable. Queue de synchronisation + localStorage pour présence et journal. Sync automatique au retour réseau.

4. Intégration Gamification

Lever le système de gamification existant (badges, classement) pour motiver les élèves (présence, comportement) et les enseignants (journal à jour).
