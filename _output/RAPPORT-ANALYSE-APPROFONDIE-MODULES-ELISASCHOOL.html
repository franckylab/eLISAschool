03 — Notes/Devoirs/Interros/Concours — Typage vs Modules séparés

✅ Verdict : Le TYPAGE suffit — PAS de modules séparés L'enum TypeEvaluation existant couvre déjà tous les cas. Créer des modules séparés (devoirs, interrogations, concours) serait une erreur architecturale (duplication, complexité, maintenance).

INTERROGATIONContrôle surprise, test courtConfigurableClasse/MatièreNON — Type suffit
EXAMENComposition officielle, partielConfigurableClasse/ÉtablissementNON — Type suffit
PROJETTravail long terme, exposéConfigurableClasse/MatièreNON — Type suffit

🆕 Extension recommandée — Ajouter CONCOURS au TypeEvaluation

// Extension TypeEvaluation — AJOUTER 3 valeurs
export enum TypeEvaluation {
  DEVOIR = 'DEVOIR',
  INTERROGATION = 'INTERROGATION',

  CONCOURS = 'CONCOURS', // ← NOUVEAU: Concours interne/classe
  COMPOSITION = 'COMPOSITION', // ← NOUVEAU: Composition officielle (période)
  EVALUATION_CONTINUE = 'EVALUATION_CONTINUE', // ← NOUVEAU: APC

}

⚠️ Cas particulier : Concours et Compositions Les concours (inter-classes, inter-écoles) et compositions (officielles de fin de trimestre) peuvent avoir un workflow spécial (classement, tableau d'honneur). Solution : ajouter un champ estClassement: boolean et rangMax: int sur Note, activé uniquement pour type=CONCOURS/COMPOSITION.

🔄 Stratégie de consolidation

Recommandation : Fusion partielle

NE PAS fusionner scoring et gamification en un seul module. Ils ont des rôles distincts :

  • Scoring = mesure quantitative (scores 0-100, rangs, moyennes) → alimente Bulletins
  • Gamification = motivation (points, badges, niveaux) → alimente Discipline/Présence

MAIS créer un AppreciationService unifié qui agrège les deux pour la vue 360° de l'élève.
