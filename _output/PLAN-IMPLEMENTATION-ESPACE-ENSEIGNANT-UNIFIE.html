1.2 Principes directeurs unifiés

🧩 Autonomie

Chaque module désactivable sans impact. Graceful degradation : si Présence inactif → scoring ignore ASSIDUITÉ.

🔗 Intégration Events

EventEmitter pour couplage faible. presence.enregistre, discipline.incident.cree, journal.seance.terminee.

🌍 Multi-Tenant Strict

TOUTE entité a etablissementId. RLS PostgreSQL. Correction des 8 entités orphelines scoring/gamification.

📋 Nomenclatures CRUD

Pas d'enum figé. 7 tables configurables par établissement. Pattern NomenclatureService<T> réutilisable.

🌍 Contexte africain

Effectifs 60-120 élèves. Appel rapide (<2 min). Mode hors-ligne PWA. Saisons rurales. Tenue uniforme.

📊 Évaluation unifiée

Fusion scoring+gamification en un seul système. Score 0-100, badges, classement, règles configurables.

3.1 Entité de base — Pattern commun

@Entity('nomenclature_{type}')
@Index(['code', 'etablissementId'], { unique: true })
@Index(['etablissementId', 'statut'])
export class Nomenclature{Type} {
    @PrimaryGeneratedColumn('uuid')
    id!: string;

    @Column({ type: 'varchar', length: 50 })
    code!: string;              // Code unique (ex: 'MALADIE', 'RETARD')

    @Column({ type: 'varchar', length: 200 })
    intitule!: string;          // Libellé affiché

    @Column({ type: 'varchar', length: 20, default: 'ACTIVE' })
    statut!: string;            // ACTIVE | INACTIVE | ARCHIVEE

    @Column({ default: true })
    estSysteme!: boolean;       // true = valeur système (non supprimable)

    @Column({ type: 'int', default: 0 })
    ordre!: number;             // Ordre d'affichage

    @Column({ type: 'jsonb', nullable: true })
    metadata?: any;             // Données spécifiques (JSONB)

    @Column({ type: 'uuid' })
    etablissementId!: string;   // Multi-tenant strict

    @Column({ type: 'varchar', length: 50, nullable: true })
    categorie?: string;         // Catégorisation optionnelle

    @Column({ default: true })
    estVisibleEnseignant!: boolean;  // Visible en mode enseignant

    @CreateDateColumn()
    createdAt!: Date;

    @UpdateDateColumn()
    updatedAt!: Date;
}

3.3 Pattern NomenclatureService<T> abstrait

export abstract class NomenclatureService<T extends NomenclatureBase> {
    protected repo: Repository<T>;

    constructor(entity: EntityTarget<T>) {
        this.repo = AppDataSource.getRepository(entity);
    }

    async findAll(etablissementId: string): Promise<T[]> {
        return this.repo.find({
            where: { etablissementId, statut: 'ACTIVE' },
            order: { ordre: 'ASC', intitule: 'ASC' }
        });
    }

    async create(dto: CreateNomenclatureDto, etablissementId: string): Promise<T> {
        // Vérifier unicité code + etablissementId
        const existing = await this.repo.findOne({
            where: { code: dto.code, etablissementId }
        });
        if (existing) throw new AppError('Code déjà utilisé', 409, 'CODE_EXISTS');
        return this.repo.save(this.repo.create({ ...dto, etablissementId }));
    }

    async delete(id: string, etablissementId: string): Promise<void> {
        const item = await this.repo.findOne({ where: { id, etablissementId } });
        if (!item) throw new AppError('Non trouvé', 404, 'NOT_FOUND');
        if (item.estSysteme) throw new AppError('Valeur système non supprimable', 403, 'SYSTEM_ITEM');
        await this.repo.remove(item);
    }

    async getValeursSysteme(etablissementId: string): Promise<T[]> {
        return this.repo.find({
            where: { etablissementId, estSysteme: true },
            order: { ordre: 'ASC' }
        });
    }
}

    constructor() { super(NomenclatureMotifAbsence); }
}

4.2 Flux d'appel — Contexte africain

Adaptation terrain : Effectifs 60-120 élèves → appel rapide par défaut PRÉSENT + exceptions. L'enseignant ne marque QUE les absents/retards (mode négatif). Temps cible : <2 minutes par cours.

Flux d'appel complet

  1. Initialisation : L'enseignant ouvre l'appel du cours (HeureCours du jour) → Auto-création AppelCours + pré-remplissage PresenceEleve avec statut=PRESENT pour tous les élèves
  2. Mode négatif : L'enseignant ne modifie QUE les exceptions (ABSENT, RETARD, etc.) → Interface rapide : swipe ou tap sur l'élève → menu 8 statuts
  3. Mode QR (optionnel) : QR code affiché au tableau → les élèves scannent → auto-marqués PRESENT → Timeout 5 min → bascule en mode manuel
  4. Clôture : L'enseignant valide l'appel → Calcul stats (presents/absents/retards) → Émission event presence.enregistre → Intégration scoring ASSIDUITÉ (non-bloquante, try/catch)
  5. Notifications : Si élève ABSENT → notification parent (SMS/push) → Non-bloquant, try/catch

// Dans le service scoring/evaluation
async recalculerIndicateurAssiduite(eleveId: string, periodeId: string): Promise<number> {
    const presenceRepo = AppDataSource.getRepository(PresenceEleve);
    const totalCours = await presenceRepo.count({ where: { eleveId } });
    const coursPresents = await presenceRepo.count({ 
        where: { eleveId, statut: StatutPresence.PRESENT } 
    });
    return totalCours > 0 ? (coursPresents / totalCours) * 100 : 100;
}

9.2 Pattern Graceful Degradation

// Pattern standard pour TOUT consommateur d'événements
eventEmitter.on('presence.enregistre', async (data) => {
    // 1. Vérifier si le module cible est accessible
    const moduleActif = await entitlementService.isAccessible(
        data.etablissementId, 'evaluation-eleves'
    );
    if (!moduleActif) {
        logger.info('[Évaluation] Module inactif — enrichissement assiduité ignoré');
        return; // GRACEFUL : pas d'erreur, pas de retry
    }

    // 2. Exécuter la logique métier
    try {
        await evaluationService.recalculerAssiduite(data.eleveId, data.periodeId);
    } catch (error) {
        // 3. Erreur non-bloquante — log + alerte monitoring
        logger.error('[Évaluation] Erreur recalcul assiduité', error);
        // PAS de throw — l'appel présence a réussi, c'est le seul engagement
    }
});

11. Risques & Mitigations

RisqueProbabilitéImpactMitigation
Perte de données scoring/gamification lors migration 224 Moyenne Critique Backup complet avant migration. Script dry-run. Validation post-migration (count, sum). Rollback plan documenté.
Rupture compatibilité ascendante — Anciens clients scoring/gamification Haute Élevé Alias de routes legacy (6 mois). Dépréciation progressive. Migration guide pour frontend existant.
Performance appel — 120 élèves par cours, temps réponse > 2s Moyenne Moyen Mode négatif (défaut PRÉSENT) = 1 requête bulk. Index sur (appelCoursId, eleveId). Pagination stats.
Connectivité limitée — Enseignants en zone sans internet Haute (contexte africain) Moyen PWA offline : queue synchronisation + localStorage. Sync au retour connexion. Mode dégradé fonctionnel.
Résistance adoption — Enseignants non-tech Moyenne Moyen Interface minimaliste (appel <2 min). Formation progressive. Mode optionnel (modules désactivables).
Couplage inter-modules — Cascade d'erreurs via events Faible Moyen Graceful degradation systématique. Try/catch sur chaque listener. Monitoring events échoués.
Multi-tenant fuite — Données inter-établissements Faible Critique RLS sur TOUTES les tables. Tests isolation systématiques. Audit queries sans etablissementId.
Scope creep — Ajouts fonctionnels en cours de route Haute Moyen Phases livrables indépendamment. Backlog priorisé. Chaque ajout = réévaluation timeline.
