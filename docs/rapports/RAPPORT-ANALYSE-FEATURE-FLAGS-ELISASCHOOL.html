1. Qu'est-ce qu'un Feature Flag ?

Définition, objectifs et contexte dans eLISAschool

Un Feature Flag (ou « interrupteur de fonctionnalité ») est un mécanisme logiciel qui permet d'activer ou désactiver une fonctionnalité sans modifier le code source ni redéployer l'application. Dans eLISAschool, ce concept est étendu à 3 niveaux complémentaires :

🚀 Feature Flags
Interrupteurs booléens par tenant pour activer/désactiver des micro-fonctionnalités (ex: notes.evaluation_continue, cantine.reservation_en_ligne)
📦 Module Gating
Contrôle d'accès aux modules complets via l'EntitlementService, lié aux abonnements et plans SaaS
⚙ Paramètres Runtime
Configuration dynamique multi-niveaux via ParametreSysteme (cascade établissement → groupe → global → défaut)
💡

Pourquoi 3 systèmes ?

Chaque système répond à un besoin distinct : FeatureFlagService gère les micro-fonctionnalités transverses, EntitlementService gère le gating des modules par abonnement (business), et ConfigurationService gère les paramètres applicatifs dynamiques. Le ConfigConsistencyService assure la cohérence entre les trois.

4. Cascade FeatureFlagService

Résolution en 3 niveaux avec override tenant

Le FeatureFlagService résout l'état d'un flag booléen pour un établissement donné en suivant une cascade de priorités. Chaque niveau peut être surchargé par le niveau inférieur.

1
Override Établissement Priorité max

Table feature_flags_tenant — valeur explicite par établissement. Source : MANUAL ou GLOBAL_OVERRIDE

2
Plan Feature Flags

Colonne JSON featureFlags dans plans_abonnement — défini par le plan d'abonnement souscrit

3
Modules Inclus (auto)

Pour chaque module dans modulesInclus du plan, un flag implicite module_{code}=true est créé

4
Défaut Fallback

false — si aucun override trouvé, le flag est désactivé par défaut

Code Source — Méthode isEnabled()

async isEnabled(etablissementId: string, flagName: string): Promise<boolean> {
  // 1. Vérifier le cache
  const cacheKey = `${etablissementId}:${flagName}`;
  const cached = this.cache.get(cacheKey);
  if (cached && Date.now() - cached.timestamp < this.CACHE_TTL) {
    return cached.value;
  }

  // 2. Override établissement (priorité max)
  const tenantFlag = await this.repo.findOne({
    where: { etablissementId, flagName }
  });
  if (tenantFlag) return tenantFlag.enabled;

  // 3. Flags du plan
  const abonnement = await this.getAbonnement(etablissementId);
  if (abonnement?.plan?.featureFlags?.[flagName] !== undefined) {
    return abonnement.plan.featureFlags[flagName];
  }

  // 4. Modules inclus (auto-flag)
  if (abonnement?.plan?.modulesInclus) {
    const moduleCode = flagName.replace('module_', '');
    if (abonnement.plan.modulesInclus.includes(moduleCode)) {
      return true;
    }
  }

  // 5. Défaut
  return false;
}

✅

Avantage clé : Source Unique

Avant l'unification, 3 registres divergents pouvaient donner des résultats contradictoires. L'EntitlementService garantit qu'un module a exactement le même état d'accès, qu'il soit vérifié par le middleware, le frontend ou un service backend.

6. Cascade ConfigurationService

Paramètres runtime — 4 niveaux + types multiples

Le ConfigurationService gère tous les paramètres applicatifs via la table parametres_systeme. C'est la source unique de vérité pour les paramètres runtime (jamais dans .env).

1
Établissement Priorité max

ParametreSysteme avec etablissementId — override local de l'établissement

2
Groupe

ParametreSysteme avec groupeEtablissementId — héritage via GroupeEtablissementLien

3
Global

ParametreSysteme avec etablissementId = NULL — paramètre global système

4
Défaut Fallback

Valeur par défaut définie dans le code ou le seed système

11. Recommandations

Améliorations proposées par ordre de priorité

R1 — Registre Centralisé des Feature Flags Priorité Haute

Créer une table feature_flag_definitions qui liste tous les flags déclarés avec : nom, description, propriétaire, date de création, date d'expiration prévue, type (release/ops/experiment/permission). Actuellement, les flags existent uniquement comme données dans feature_flags_tenant sans métadonnées.

-- Table proposée
CREATE TABLE feature_flag_definitions (
  id uuid PRIMARY KEY,
  name varchar(200) UNIQUE NOT NULL,
  description text,
  owner varchar(100),        -- équipe/module responsable
  type varchar(30),          -- release|ops|experiment|permission
  created_at timestamptz DEFAULT now(),
  expires_at timestamptz,    -- alerte si dépassé
  est_systeme boolean DEFAULT false
);
R2 — Progressive Rollout (% Rollout) Priorité Haute

Ajouter la capacité d'activer un flag pour un pourcentage d'établissements (hash stable sur etablissementId). Pattern standard : hash(etabId) % 100 < rolloutPercent. Permet le déploiement progressif sans risque.

R3 — UI d'Audit des Toggles Priorité Moyenne

Créer un onglet « Historique » dans le Feature Flags Manager montrant : qui a toggled quoi, quand, ancienne/nouvelle valeur. Utiliser l'AuditLog existant avec cible='FeatureFlag'.

R4 — Expiration Automatique des Flags Priorité Moyenne

Les flags de type « release » doivent avoir une date d'expiration. Après expiration : alerte dans le consistency checker + suggestion de suppression. Le cron cleanup-flags-expired peut être ajouté.

R5 — Targeting par Segments Priorité Moyenne

Ajouter la capacité de cibler des segments d'établissements : par type (« tous les lycées »), par plan, par groupe, par taille. Pattern : segments JSONB dans feature_flag_definitions avec règles d'évaluation.

R6 — A/B Testing Multi-Variant Priorité Basse

Pour les expérimentations : supporter des variants (A/B/C) avec pondération. Modèle : variants: [{name: 'control', weight: 50}, {name: 'treatment', weight: 50}]. Hash stable pour assignation cohérente.

R7 — Feature Flag Debt Dashboard Priorité Basse

Dashboard montrant les flags « endettés » : actifs depuis > 90 jours, sans description, sans propriétaire, ou expirés. Règle industrielle : tout flag de type « release » doit être nettoyé dans les 30 jours après déploiement complet.

R8 — SDK Client Unifié Priorité Basse

Créer un hook React unifié useFeatureManagement() qui combine : flags (FeatureFlagService), modules (EntitlementService), et paramètres (ConfigurationService) en un seul point d'entrée avec cache partagé.
