1. Vue d'ensemble architecturale

3. Cascade 4 niveaux — Resolution des parametres

Le systeme implemente une cascade de resolution a 4 niveaux. Chaque niveau peut override le precedent. La priorite decroit du plus specifique (etablissement) au plus general (systeme).

1

Etablissement (Tenant)

etablissementId IS NOT NULL — Override specifique a un etablissement

Priorite MAX
2

Groupe SaaS

groupeEtablissementId IS NOT NULL — Override pour un groupe d'etablissements

Priorite 2
3

Global (Systeme)

etablissementId IS NULL AND groupeEtablissementId IS NULL — Valeur globale

Priorite 3
4

Defaut code / Seed

valeurDefaut dans l'entite ou MODULE_REGISTRY.defaultActive

Fallback

6. Securite — Defense en profondeur

La securite du systeme de configuration repose sur 6 couches de protection : chiffrement, isolation RLS, controle d'acces RBAC, audit trail, gestion de cles, et validation.

🔒

AES-256-GCM

Chiffrement des parametres ENCRYPTED. IV unique 16 bytes. AuthTag integrite. Format iv:authTag:cipher en base64.

🛡

PostgreSQL RLS

40+ tables avec Row-Level Security. Policy : etablissementId = current_setting('app.current_tenant'). Bypass SUPER_ADMIN via sentinelle UUID.

👥

RBAC 22 permissions

18 permissions granulaires config + 4 platform-scoped. Guards par endpoint. Roles : SUPER_ADMIN, ADMIN, CHEF_ETABLISSEMENT.

📝

Audit Trail complet

HistoriqueConfiguration + ParametreVersion. Actions : CREATE, UPDATE, DELETE, RESET, IMPORT, EXPORT, RESTORE. Rollback possible.

🔑

KeyManager

4 types de cles (JWT, ENCRYPTION, MFA, AUDIT_HMAC). Rotation automatique 90 jours. Grace period 7 jours. Statuts : ACTIVE, ROTATION, REVOQUEE.

✅

Validation Zod

Chaque parametre peut avoir une expression de validation. Types coercés automatiquement. Protection contre injection de types.

7. Performance — Optimisations

Le systeme est concu pour minimiser la charge sur PostgreSQL et offrir des temps de reponse sub-millisecondiques pour les lectures de configuration.

7.2 Optimisations cles

📚 PgBouncer

Mode transaction, pool 20 connexions, max 200 clients. Recyclage automatique des connexions (maxUses=1000).

📊 AsyncLocalStorage

Contexte tenant propage via AsyncLocalStorage. Pas de passage explicite de etablissementId dans chaque appel de service.

🔌 Transaction conditionnelle

RLS : transaction uniquement sur les writes (POST/PUT/PATCH/DELETE). Les GET utilisent SET LOCAL sans transaction (plus leger).

📈 Index composites

Index unique (cle, etablissementId) sur ParametreSysteme. Index partiels RLS sur 40+ tables. Index sur categorie, module.

🚀 Batch queries

Monitoring : flush interval 10s. Stockage Redis time-series (sorted sets). Agregation par fenetre de 10s, TTL 24h.

💾 Seed optimise

~100+ parametres seeds en une seule transaction. Upsert idempotent par (cle, etablissementId). 41 modules via ON CONFLICT.

10.2 Points forts

✓
Source unique de verite

ParametreSysteme remplace ConfigurationApp. Plus de divergence entre 3 registres. ModuleCatalogue unifie les definitions.

✓
Cascade elegante

4 niveaux (Etablissement → Groupe → Global → Defaut) avec propagation, rollback et detection d'incoherences.

✓
Chiffrement transparent

TypeValeur ENCRYPTED avec chiffrement/dechiffrement automatique. L'utilisateur du service ne voit pas la complexite crypto.

✓
Isolation multi-tenant

RLS PostgreSQL sur 40+ tables + middleware fail-closed + cross-plane guard. Defense en profondeur a 3 niveaux.

10.3 Axes d'amelioration

⚠ Cache cold start

Au demarrage d'une instance, le cache est vide. Envisager un warm-up preload des parametres critiques (modules actifs, feature flags).

⚠ Partitionnement parametres

Avec la croissance, la table parametres_systeme pourrait beneficier d'un partitionnement par etablissementId (hash) pour les gros deploiements.

💡 Configuration UI temps reel

WebSocket pour notifier les admins etablissement des changements de configuration en temps reel (plutot que polling).

💡 Schema validation avance

Etendre la validation Zod a tous les types (pas seulement STRING). Validation structurelle pour JSON/ARRAY avec schema stocke dans validation.

🏆
Conclusion — Score global 9.5/10 Le systeme de configuration d'eLISAschool est une implementation de qualite enterprise. L'architecture en cascade 4 niveaux, le cache distribue, le chiffrement AES-256-GCM, l'isolation RLS et le catalogue module unifie constituent une base solide pour un SaaS multi-tenant. Les quelques axes d'amelioration sont des optimisations, pas des failles architecturales.
