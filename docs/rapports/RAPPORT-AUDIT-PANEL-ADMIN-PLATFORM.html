5 Benchmark vs meilleures pratiques SaaS

❌ eLISAschool actuel

  • 10 groupes, 37 items — trop granulaire
  • Feature Flags dans 4 endroits
  • Configuration = 4 pages en 1
  • Monitoring = 9 sections sans tabs
  • Fichier 3,935 lignes
  • 0 composant Panel/Card partagé
  • 13 sidebar items → 4 routes (?tab=)
  • Couplage admin↔platform

  • 4-6 groupes, max 20 items
  • 1 feature = 1 page dédiée
  • Settings = paramètres uniquement
  • Monitoring = tabs clairs (3-4 max)
  • Max 400 lignes par composant
  • Design system avec primitives partagées
  • 1 sidebar item = 1 route unique
  • Séparation stricte des features

9 Plan de migration

Approche : Migration directe et brutale sans intermédiaires

Pas de période de transition, pas de double-routes, pas de deprecated warnings. Suppression + remplacement immédiat.

Phase 1 — Composants partagés P0 — 1 jour
  • Créer components/ui/platform/PlatformCard.tsx
  • Créer components/ui/platform/DetailPageLayout.tsx
  • Créer components/ui/platform/StatCard.tsx (version platform)
  • Remplacer les 25+ occurrences de card styling
  • Remplacer les 3 detail page shells
Phase 2 — Décomposition etablissement-detail P0 — 1 jour
  • Extraire les 7 tabs dans features/platform/components/etablissement-detail/tabs/
  • Extraire les utils dans components/detail-utils.tsx
  • Shell etablissement-detail-page.tsx → ~200 lignes
  • Remplacer les 6 appels apiClient directs par des hooks TanStack Query
Phase 3 — Élimination redondances Feature Flags P0 — 0.5 jour
  • Supprimer FlagsTab de platform.facturation.tsx
  • Supprimer FeatureFlagsManager overlay de platform.configuration.tsx
  • Garder platform.fonctionnalites.tsx comme source unique
  • Déplacer sidebar item "Fonctionnalités" du groupe Catalogue → groupe Système
  • plan-form-modal : remplacer liste hardcodée par hook API
Phase 4 — Élimination redondances Groupes + Cascade P1 — 0.5 jour
  • Supprimer tab "groupes" de platform.facturation.tsx
  • Supprimer platform.configuration-cascade.tsx (doublon de parametres-cascade)
  • Garder /platform/groupes comme source unique GroupesSaaSPage
  • Garder /platform/parametres-cascade comme source unique cascade
Phase 5 — Éclatement facturation en pages dédiées P1 — 1.5 jours
  • Extraire PlansTab → platform.plans.tsx (page dédiée)
  • Extraire AbonnementsTab → platform.abonnements.tsx (page dédiée, remplacer redirect)
  • Extraire FacturesTab → platform.factures.tsx (page dédiée)
  • Extraire UsageMetersDashboard + RevenusDashboard → platform.revenus.tsx (page dédiée, remplacer redirect)
  • Supprimer platform.facturation.tsx (la mega-page 7 tabs)
  • Fusionner Remises + Packs Quota + Cycles → platform.commerce.tsx ou pages séparées
Phase 6 — Nettoyage configuration P2 — 0.5 jour
  • configuration : garder uniquement paramètres système/sécurité/régional
  • Supprimer section "modules" (doublon avec /platform/modules)
  • Supprimer section "notifications" (doublon avec /platform/notifications)
  • Extraire backup/historique/restore → platform.backups.tsx (page dédiée)

Phase 7 — Refonte sidebar + monitoring + CommandPalette P2 — 1 jour

  • Supprimer routes redirect-only : platform.revenus.tsx (ancien), platform.debug.index.tsx

11 Questions de validation

Q1 — Fusion Remises + Packs Quota + Cycles Stratégies ?

Actuellement 3 pages séparées dans le groupe Catalogue. Options :

  • A. Fusionner en 1 page "Commerce" avec 3 tabs (recommandé — même domaine fonctionnel)
  • B. Garder séparés mais déplacer dans groupe "Facturation"
  • C. Garder séparés dans groupe "Catalogue" (statu quo)

Q2 — Sort du groupe "Debug" ?

3 items (Entitlements, API, Features) — uniquement pour développeurs. Options :

  • A. Supprimer du sidebar, accessible uniquement via CommandPalette (Ctrl+K) (recommandé)
  • B. Garder mais ajouter un flag "mode développeur" pour afficher/masquer
  • C. Garder tel quel

Q3 — Sort de la page "configuration" ?

Actuellement 7 sections dont 4 ont des pages dédiées ailleurs. Options :

  • A. Réduire à 3 sections (paramètres système, sécurité, régional) — le reste va dans ses pages dédiées (recommandé)
  • B. Supprimer complètement — chaque catégorie a sa propre page
  • C. Garder tel quel

Q4 — Fichier etablissement-detail (3,935 lignes) — décomposition ?

  • A. 9 fichiers (1 shell + 7 tabs + 1 utils) — chaque tab est autonome (recommandé)
  • B. 5 fichiers (1 shell + 3 tabs groupés + 1 utils) — moins de fichiers
  • C. Garder tel quel mais extraire uniquement les utils partagés

Q5 — Ordre des phases de migration ?

  • A. Séquentiel P1→P7 (composants partagés d'abord, puis refonte progressive)
  • B. Big bang : tout en 1 session (plus rapide mais plus risqué)
  • C. Priorité risques : P3/P4 (redondances) → P5 (facturation) → P1/P2 (composants) → P6/P7
